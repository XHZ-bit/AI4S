## 实现内容

### 自动抽取范围

- 接受冻结的 `ExtractionInput`，校验 project、paper link、document、document version 和每个 passage 的归属一致性。
- 复用 `app.llm.client.chat`；不读取配置密钥，不写数据库，不调用 T3/T4/T5。
- 每个非表格 passage 独立调用模型和装配候选，避免把跨段信息拼成一次原文中不存在的实验。
- 返回公共 `CandidateBundle`：
  - `MethodCard`：方法名、任务、摘要、输入输出、机制、假设和限制；
  - `ExperimentSetting`：同一方法可保留多个设置，设置不会按方法名或数据集自动合并；
  - `Measurement`：严格绑定一个具体 setting，不只保留最高值；
  - `EvidenceRef` 与逐字段 `FieldEvidence`；
  - 机器可读 warning 前缀和 `extraction_version`。
- 区分 `current_paper_method | cited_method | comparison_method | unclear`：
  - 当前论文方法设置 `paper_link_id`；引用、对比或归属不明的方法不冒充当前论文方法；
  - 归属角色和作者文本保存在方法 `name` 对应的 `FieldEvidence.note` JSON 中；
  - 被引用作者的设置和结果绑定其独立 method/setting ID。
- 所有事实保持 `candidate`；引用定位成功不等于用户确认，也不表示科学结论正确。
- 缺失字段保留 `unknown/not_parsed/not_found/conflicting` 状态，不从方法名推断资源、数据集或性能。
- 数值测量、资源/超参数值、方法/设置/数据集/指标名称增加词面落地检查；关键值未出现在绑定原文时降级为 `not_parsed`，不发布该值。
- 方法、设置、测量和证据 ID 由冻结文档、passage、局部 ID 和位置稳定派生，可供 T1 缓存与审计。
- 提示词版本为 `research-extraction-prompt-v1`，私有输出 schema 版本为 `research-extraction-schema-v1`；组合值写入 `CandidateBundle.extraction_version`。

### 证据验证

- 模型只能引用当前正在处理的 passage；伪造 passage ID、document ID、页码或 heading 会被拒绝。
- quote 必须是当前 passage 的连续逐字子串；offset 由 T2 在输入文本中重新计算，不接受模型提供的 offset。
- 无有效证据的 reported 字段降级为 `not_parsed`；核心方法名、设置名或指标名没有有效证据时不创建相应候选。
- 文档中的提示注入、命令或角色指令作为资料传给 user message；system message明确禁止执行或服从。
- 单个 passage 的非法 JSON、schema 错误或模型失败会生成 `passage_failed` warning，其他 passage 可继续；所有合格文本 passage 都失败时抛出明确异常。
- 单一非法 JSON 抛 `ModelOutputError`；全部超时或模型不可用抛 `ModelInvocationError`；混合全失败抛 `ExtractionBatchError`；输入不一致抛 `ExtractionInputError`。
- 有效模型响应但没有候选时返回 `no_automatic_candidates_found`，不伪装为完整抽取成功。

### 必须人工补录或确认

- 表格 passage 不进入模型。T2 返回 `EvidenceKind.TABLE + FindingStatus.NOT_PARSED`，保留 page、heading、table ID、行列标签，并添加 `table_requires_manual_confirmation`；表格数字必须由用户确认/补录。
- 图片、公式、OCR 错误、损坏表格以及跨 passage 才能建立的实验关系未做通用自动解析。
- 精确文本匹配只证明引用存在；语义蕴含、作者真实意图、实验正确性和科学结论仍需人工核验。
- 同名方法不会自动合并，跨 passage 的重复候选由后续人工审核或 T1 的版本化流程处理。
- `not_found` 只在模型明确返回且值为空时保留；T2 不根据单个 passage 的缺失擅自宣称整篇论文未报告。

## 对其他任务的依赖

- 依赖 T0 冻结的 `app.models.research` 中 `ExtractionInput`、`CandidateBundle` 及事实/证据模型。
- 依赖现有 `app.llm.client.chat`。模型未配置或不可用时明确失败；无真实模型降级成功结果。
- T1 负责调用、缓存、持久化、任务状态和 API 错误映射；T2 不接触数据库。
- T1 传入 passage 时可直接使用旧 `document_view` 行结构：`id/document_id/text/page/heading/kind/ordinal/metadata_json`。也支持 `passage_id` 和 `section` 别名，但未知字段会按严格输入校验拒绝。

## 接口或公共文件变更申请

- 当前公共 `MethodCard` 没有一等的 `claim_role`/`attributed_to` 字段。T2 为不越权修改公共模型，暂将其编码为方法 `name` 的 `FieldEvidence.note` JSON，并用 `paper_link_id` 是否存在区分当前论文方法与其他方法。
- 建议 T0 后续评估在公共模型中增加显式、枚举化的方法归属字段，例如：
  - `claim_role: current_paper_method | cited_method | comparison_method | unclear`
  - `attributed_to: str | null`
- 若 T0 接受该变更，T2 应改为直接填充公共字段，并保留 `FieldEvidence` 作为字段来源，不再把归属元数据放在 note 中。
- 本轮没有修改任何公共文件或接口契约。
