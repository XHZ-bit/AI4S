# 本机源码教学使用说明

打开 http://localhost:5173/cases/diffusion-policy-intro ，点击“开始学习并保存进度”。这个专题可以不调用模型、不连接图数据库，直接查看固定版本的源码和教学步骤。

## 本轮已经提供
- 5 个步骤：明确范围、理解接口、核对配置、执行源码检查、解释结果。
- 8 个定位到固定提交和行号的源码关联。
- 4 道理解检查：按预设答案反馈，答错后可以回到对应步骤。
- 独立学习记录、刷新恢复、版本冲突提示和历史检查记录。
- 标准库检查工具、离线源码包、结果 JSON 导入和 Markdown 报告。
- 6 类常见困难提示，不自动运行第三方代码。

## 在自己的电脑运行
1. 在“运行本机检查并导入结果”下载 atlas_case_check.py 和 atlas-sources.zip。
2. 将源码 ZIP 解压到 atlas-sources 文件夹，工具放在同一级目录。
3. 在该目录打开终端：
   python atlas_case_check.py --source-dir atlas-sources --output atlas-result.json
4. 将 atlas-result.json 导入页面，检查每项结果。输出文件已存在时，改用 atlas-result-2.json，保留历史。
5. 完成范围判断题，再导出学习与检查报告。

工具只要求 Python 3.10+，不需要 torch，不会加载模型、下载权重、训练或评估策略。省略 --source-dir 可从固定官方地址读取约数 KB 源码；网络不可用时使用离线包。

## 结果意味着什么
服务端核对提交版本、文件散列、检查项和必需字段。这是用户导入记录的一致性检查，不是独立执行认证。失败的最新记录会明确显示，不会被旧成功记录掩盖。用户改写 JSON 并不能构成真实实验的证明。
选定源码与上游固定版本一致，也不代表 Diffusion Policy 的性能已复现。模型下载、GPU 运行和真实策略评估按用户决定暂缓。

## 数据与恢复
案例进度独立存入 SQLite 新表，不改原论文工作区。数据库与已有文件在本次部署前已备份到 .local-backups（不公开）。本机单用户模式，不作为公网多用户权限系统使用。
