# 学习资源展示与产品提示整理

用户反馈资源区反复显示“并非已经找到的特定资源”“尚未检测访问”等说明，影响阅读和产品完成度。检查发现该节点的三个条目实际为站外搜索入口，却计入资源数量并逐条附加两层机制说明。

## 已实施

- 将具体学习资料与站外搜索分开。搜索入口以哔哩哔哩、YouTube和学术搜索的一组链接展示，不计入资料数量或类型筛选。兼容旧记录中类型错误但URL属于已知搜索页的入口。
- 资料列表默认显示标题、类型、来源网站及实质用途；来源分类、内容读取、访问记录和核对日期放入“资源详情”。未知状态不显示为访问成功，链接核对不宣称科学内容可靠。
- 无资料显示简短空态及添加链接操作。访问失败或地址无效保留就地提示，支持添加替代链接；刷新失败保留当前资料，保存失败保留输入，错误细节可展开。
- 视频和图片继续按用户操作加载，保留外站回退和原文证据定位。用户添加的图片仅称“图片”，有原文证据时再提供定位。
- 问答中的运行机制放入“回答说明”，按实际结果区分AI辅助回答、原文摘录和已保存内容摘录。缺依据、生成失败、来源变化及未知警告仍保持可见。
- 用户保存的AI分析按组标识为“AI学习记录”，每条保留日期与内容。以上规则写入 DESIGN.md，供后续页面沿用。

未新增后端接口、访问检测或实际资源搜索能力；“刷新资源”仍是重新读取资料列表。没有把站外搜索包装成已经检索到的内容，也未修改正常资料库、模型配置或用户的核对记录。具体资源供给需要继续按主题维护课程、视频和代码目录，不能由界面展示数量推断覆盖质量。

## 验证

五个相关前端文件42项检查通过，记录 `.tmp/resource-ui-final-tests.log`，包含资源分类与计数、筛选、历史证据字段、失效链接恢复、跨节点迟到请求、问答来源与重要警告可见性，以及既有视频和笔记入口。生产构建通过，记录 `.tmp/resource-ui-build.log`；原有主包超过500kB的提示保留。

实际Chrome的7项流程通过，脚本 `evaluation/research_atlas/run_resource_presentation_browser.cjs`，报告 `.ui_validation/resource-presentation-20261117/report.json`。检查1366、1920及125%等效1152宽度，包含浅深主题、搜索空态、混合资料、详情、筛选、添加替代链接、请求失败与按需视频。七张截图已逐张检查，无整页横向溢出。

浏览器使用真实前端、独立上下文及自编模拟API，视频由HTML替身提供；没有访问用户账号、正常资料库、外站或模型。页面异常、意外控制台和HTTP错误及模型请求均为0。一次主动模拟的503及其控制台记录归入预期错误，用于核验失败后的内容保留及重试。

截图与报告用于界面和交互验收，不证明链接现在可访问、资源相关性已通过真人评估或科研内容已独立核实。未启动新的服务，当前前端刷新后即可使用改动。
