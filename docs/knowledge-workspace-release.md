# PaperStride 独立研究空间交付说明

日期：2026-10-29。本文根据本轮实际代码说明功能入口、数据边界、运行配置和迁移方式。需求背景见[两轮交流需求分析](knowledge-workspace-requirements.md)，真实材料的覆盖、公式正确性、模型用量、耗时及未通过项目的结果见[验收记录](validation/knowledge-workspace-2026-10-29.md)。功能已实现不表示每个自动知识判断均已人工核验。

## 1. 从一个研究空间开始

打开“研究空间”，创建空间时选择“零基础探索”“已有思路深入研究”或“阅读与复现”。模式保存在空间中，可在工作台切换。模式提供学习上下文和默认侧重，不删除已有知识，也不限制视图使用。

空间默认工作台有五个主要视图：

| 视图 | 如何使用 |
|---|---|
| 研究图谱 | 浏览空间总览；选择资料进入拆解图；搜索知识、展开节点、查看关系解释和依据 |
| 原文阅读 | 选择资料，连续阅读 PDF 或按章节、代码行、表格位置查看其他资料；从当前位置进入关联知识 |
| 深入学习 | 从节点进入宽屏讲解，展开前置知识、公式与实现，运行适用教学演示，再返回原位置 |
| 方法比较 | 选择两份及以上资料，按需聚焦每份资料中的一个具体方法；查看有依据的逐项对照 |
| 资料与记录 | 上传、关联已有论文、添加公开链接，查看分阶段进度、继续分析和研究记录 |

建议先在“资料与记录”上传论文和报告，等待结构图出现，进入“研究图谱”查看单篇结构与语义节点，再选择具体方法比较。分析部分完成时可先阅读原文和已生成内容，并按缺失阶段继续处理。

默认新空间有 1—3 份资料时优先单篇焦点，达到 4 份时优先总览。手动选择的视图优先保存。地址中的 `view/source/node/page/block/comparison` 等参数明确当前场景；浏览器按空间保存有限的最近导航位置，显式地址参数优先。账号切换清除相关浏览器状态。

## 2. 资料、来源与处理过程

### 2.1 入口与格式

可从当前空间上传文件、关联已有论文，或添加论文/公开代码仓库链接。文件种类可自动判断，也可显式选择论文、研究报告、实验结果或代码。

实现支持 PDF，DOCX，Markdown/TXT，CSV/XLSX/JSON，以及选定代码文件。Python 解析进一步提供类、函数及行号；JavaScript、TypeScript、C/C++ 等首先按文本与文件行定位。文件上限为 50 MB，空文件会拒绝。链接获取也有大小和地址校验，不会根据报告中的本机路径自动导入文件。

本轮实际使用的个人资料只有用户提供的原始 `臂手协同PPO论文探索阶段总结.docx`。用户已明确不导入个人源码与结果文件，因此报告中的代码路径和实验陈述保留为报告内容或待补充来源。源码查看采用公开 CoorDex 仓库的固定版本文件快照，首批进一步加入了实际的 [`actor_critic_coord_residual.py`](https://github.com/Skevinci/coordex/blob/9a5dfe0f52efd2624507f8cc9ed117aef6ef7472/source/coordex/coordex/policies/actor_critic_coord_residual.py)；该文件固定于提交 `9a5dfe0f52efd2624507f8cc9ed117aef6ef7472`，属于公开论文实现来源。

### 2.2 四个独立阶段

| 阶段 | 保存的成果 | 部分完成的含义 |
|---|---|---|
| 原文保存 | 原始文件、内容哈希、空间资料关联 | 文件已保留，后续阶段仍可继续 |
| 结构解析 | 章节、正文、公式/图片/表格等内容块和定位 | 文本或结构可用，但某些版式、公式等未可靠识别 |
| 知识抽取 | 研究问题、方法、概念、实验等有依据的节点与关系 | 当前仅结构图，或部分批次/知识尚缺失 |
| 图谱更新 | 空间组织、跨资料联系与前置知识入口 | 已有图可用，但不代表全文语义覆盖完整 |

界面分别显示四阶段状态、错误和提示，原文可读与语义完成不会共用一个“解析成功”标志。公式覆盖可在资料质量信息中查看；可识别或渲染并不代替逐项核对符号、上下标和适用条件。

上传自动排队，活跃任务在空间内更新进度。队列满时保留原文并给出继续入口。解析在独立后台子进程执行，本机默认串行；取消会终止正在进行的解析进程。已经提交给外部模型的单次请求按调用结果结束，后续阶段检查取消状态。

失败、取消、预算用尽或重启不会删除已经保存的内容。重启将运行中任务标为“已中断”，由用户选择继续；服务不会因此自动重放付费任务。继续分析复用已有基础解析和可复用的语义批次，按当前来源版本补充缺失部分。

### 2.3 来源定位与固定版本

每个来源具有内容版本，基础解析拆为 `SourceBlock`。证据引用来源版本与内容块，并按类型保存定位：

- PDF：页码和可用时的原始页面坐标，打开时高亮对应区域。
- DOCX/文本：章节与段落/内容块序号；DOCX 公式保留 OOXML 数学表达提取结果。
- Python/代码：文件、类或函数、起止行；公开仓库进一步保存文件路径、提交与固定 URL。
- 表格：工作表和单元格范围，并保留可展示的单元格内容。

图像、图注和无法可靠转写的公式保留可检查来源。部分公式使用有界的图像转写补充，按需学习中的公式补充计入该次学习预算。公式节点可在空间内编辑 LaTeX，并预览显示；人工修订不修改共享原文件。

公开 GitHub 仓库链接被解析为一个固定提交的**选定文件快照**，保存仓库、提交哈希、文件路径、文件内容与哈希以及选择覆盖信息。界面可打开文件固定链接并显示短提交；“下载仓库快照”下载保存的 `.repo.json` 清单。它并非完整仓库克隆，也不会执行仓库代码。

如果已经明确选定文件，可直接粘贴 `https://github.com/组织/仓库/blob/40位提交哈希/文件路径`。对支持的 Python/Markdown/文本文件，服务直接读取该固定提交的原始文件并形成单文件快照，避免为这一步消耗 GitHub 仓库树和提交查询 API 的配额。普通仓库或分支链接仍先解析提交和候选文件；出现 API 限流时，可改用已知提交的单文件链接，或者上传已取得的文件。

## 3. 空间独立与可修订知识

同一账号内，相同文件内容可复用原文件和基础解析。各空间的节点、关系、补充说明、学习内容、研究记录、人工修订和隐藏状态独立保存；服务端同时校验账号、空间和来源。账号资料目录沿用现有隔离方式。

研究图谱包括空间总图、资料或方法拆解、节点邻域三个层次。总览投影展示资料根节点与跨资料关系，避免数百章节和概念挤占初始画布；详细节点通过单篇、搜索、类型筛选和邻域展开访问。投影关系保留原始知识端点和依据，进入关系检查时可核对真正关联的模块。

节点显示内容性质和研究状态：原文明示、平台归纳、用户补充；未说明、设想、已实现、报告中已完成、待验证。用户可以修改名称、解释、研究状态及公式内容，隐藏或恢复节点/关系；对确定同一性的节点可合并，再拆分恢复成员。不能仅因标签相同就把不同上下文的变量或方法当成同一实体。

节点和关系修订采用版本检查。来源再分析保留用户修改字段，追加处理和修订历史。移除来源会给依赖知识标记“来源缺失”，不清空用户记录；资料列表可查看并恢复移除项。学习与比较依据变动后提示需要复核，不能把旧缓存误当作最新结论。

研究报告中的历史实验结果是报告的陈述；平台保留其来源、日期与状态，不把它改写为独立复现实验结论。没有上传的个人源码和结果不自动补成已核实证据。

通用 `context` 处理从实际保存的报告内容块中识别“截至/更新/记录”等日期线索，并保存日期值、精度及对应块和原句；不能仅以文件名日期推断报告时点。资源引用也从对应证据及同章节的相邻路径内容块识别，再与当前空间实际上传文件和已获取的仓库文件清单核对。不能把公开仓库中的同名文件当作用户本机私有实现；未提供对应文件的引用显示“待补充来源”。这一步只检查已保存的资料，不打开报告引用的本机路径，不执行代码，也不增加模型调用。人工修订字段保持受保护。

## 4. 阅读与双向导航

PDF 阅读继续使用 PDF.js，采用连续页面与可见区域按需渲染。每页按真实尺寸适应宽度，可调整缩放、全屏、输入页码跳转、打开目录和全文搜索。阅读器根据页面剩余窗口高度安排原文空间，辅助内容按需展开。

从节点或比较依据打开 PDF 时保留资料、目标页及区域；从报告、代码或表格打开时定位到对应内容块或行/单元格。阅读页显示当前位置关联的知识节点，可直接“查看关联知识”或“深入学习此处”；返回入口保存阅读场景。源码栏显示仓库文件路径和提交，报告与表格按自身定位展示。

旧工作台入口保留。显式旧 `tab=...` 链接继续使用原视图；新 `view=...` 链接使用本轮工作台，必要时可通过 `legacy=1` 打开兼容入口。已有笔记、研究记录、实践与历史快照不会因默认工作台切换而删除。

## 5. 深入学习与六个演示

读取节点学习内容使用 GET，仅返回基础内容或已有保存结果；打开页面不会自行调用付费模型。用户选择准备或更新讲解后，平台检索当前节点、原文、相邻节点、前置知识及空间目标，生成并保存讲解。

生成后进行基于同一来源上下文的一致性审阅，核对公式系数和变量、方法归属、局部梯度的适用边界、报告时间及教学补充的标记。有可应用的修订时再复核一次；生成、审阅、复核和需要时的公式图像补充共同使用单次最多 4 次请求的学习预算。审阅是模型检查，不能替代独立人工核验。缺少依据的来源事实保持未知；生成失败、来源审阅失败或原始公式仍不可靠时，保留基础内容和原文，并以 `partial/basic` 表达可用范围。`ready` 表示本次处理流程完成，不表示讲解已经独立科学核验。验收中按实际来源复核过的内容以版本化修订保存，范围与局限见验收记录。

主视图包括直观理解、原文定义、公式与推导、前置知识、实现与演示、适用边界。前置节点可以继续进入，用户按需补基础。实际提供的代码可按文件、类、函数和行号查看；没有代码依据时保留缺失提示，教学示例与论文实现分开说明。

六个讲解区域各有“修订讲解”和隐藏/恢复入口。修订可以直接保存，不要求逐条审批；保存后标为用户补充。编辑和隐藏使用讲解修订号检查并发，冲突时保留当前草稿并提供重新读取入口。后续重新生成或来源更新保留已经人工编辑的区域和隐藏选择，并更新其余可生成部分。

资源条目记录标题、URL、类型、推荐理由及是否获取内容。仅有链接的资源作为入口；已经实际获取的内容才可被解释当作依据。保存结果按来源、节点、空间上下文和生成规则关联缓存，重复访问优先读取，内容变化提示更新。

| 演示 | 可调内容与展示 | 范围 |
|---|---|---|
| 链式法则 `chain_rule` | 输入与中间变量，局部导数与链式乘积 | 简化计算图 |
| 激活函数 `activations` | sigmoid/tanh 输入，输出与局部梯度 | 单变量函数 |
| 门控与残差 `gating` | 门控输入、残差幅度，位置和有界作用 | D1/D2 等机制的教学示意，具体对应需核对原文 |
| 高斯策略 `gaussian` | 均值、标准差和采样，概率密度 | 教学采样，与真实训练分开 |
| PPO `ppo` | 比率、优势与裁剪范围，目标函数变化 | 单样本裁剪目标 |
| 分支信息路径 `branches` | 共享与分支结构、消息连接及路径 | 结构示意，不替代完整网络训练 |

这些模块具有真实数值计算和交互参数，作为学习工具匹配节点；不执行机器人训练，不把演示结果当作论文或自己的实验结果。

## 6. 有依据的方法比较

在“方法比较”选择两份至八份资料，可以为每份资料聚焦一个已经存在的可见方法、模块、算法或研究设想节点。例如选择研究报告中的 D2，再选择相关论文的协调方法。未聚焦时按资料整体组织比较。

比较包括协调问题、模块划分、信息路径、输入与输出、训练与额外成本、实验条件与结果以及适配差异。每格保留内容性质、关联节点和证据入口；学习或阅读后可返回原比较。历史比较保存资料与聚焦节点选择，能够重新打开或按最新依据更新。

来源不完整时保留未知，条件不兼容时显示差异，不做无依据的数值排名。GET 历史比较不会调用模型；显式比较才进行生成。缓存关联来源、知识版本和方法选择，聚焦 D2 的结果不会与未限定方法的结果混用。

超过 3 份资料的多源比较按 8 个维度分为 4 组，每组先生成再进行一次来源一致性审阅；较少资料可整体生成和审阅。比较采用独立的最多 **8 次请求**预算，每完成一组即保存检查过的结果，继续时可复用已完成组。审阅核对每格的资料归属、信息路径、分支与独立智能体的区别、指标单位、原论文与适配版本以及报告时间。缺少依据的格子据实显示未知，单格未知不强制整份比较降为部分完成；`ready` 表示比较流程完成，未知仍是未知，也不表示独立科学核验。生成失败、来源审阅失败或预算中断时，以 `partial/basic` 保存已经完成或基础内容，不把没有支持的判断补成确定结论。比较的 8 次上限是本轮实现的独立默认值；原批准方案没有单独规定比较请求上限。

## 7. 实际架构与接口

保留 React + Ant Design 前端和 FastAPI 后端，新服务位于 `backend/app/knowledge/`，API 位于 `backend/app/api/knowledge.py`。本机 SQLite 是知识、任务与版本的主存储，Neo4j 不是本轮核心启动条件。

| 数据对象 | 实际作用 |
|---|---|
| 资料与版本 | `kw_assets` 保存内容身份与原文件；`kw_sources` 关联账号内空间资料 |
| 基础解析 | `kw_parses`、`kw_blocks` 保存可复用结构、质量和定位 |
| 节点与关系 | `kw_nodes`、`kw_edges`、`kw_evidence`、`kw_history` 保存空间知识、依据与修订 |
| 分阶段分析 | `kw_runs`、`kw_extractions` 保存进度和语义批次 |
| 学习与比较 | `kw_learning`、`kw_comparisons` 保存生成版本、依据与缓存 |
| 运行与偏好 | `kw_model_calls`、`kw_operations`、`kw_preferences` 保存调用、并发去重及模式/视图 |

新增接口统一位于 `/api/projects/{project_id}` 下：`/sources`、`/analysis`、`/knowledge/graph`、`/knowledge/nodes`、`/knowledge/edges`、节点 `/learning`、`/knowledge/comparisons` 和 `/knowledge/preferences`。前端统一使用账号认证请求，路由串联空间、来源、节点与返回位置。细节见[接口协作约定](knowledge-workspace-contract.md)和实际 FastAPI 路由定义。

Docling 作为结构解析主路径，PyMuPDF 用于快速文字、原文裁片和兼容。DOCX、表格、代码有各自解析器；通用流程不为验收论文编写专属抽取分支。实际解析器和降级状态在资料质量中记录，降级文本不伪称完整结构解析。

## 8. 安装、统一模型与运行默认值

在项目根目录使用现有依赖脚本：

```powershell
.\scripts\setup-dependencies.ps1
.\scripts\setup-docling.ps1 -Check
```

依赖脚本准备项目内 Python、锁定依赖、前端依赖及解析模型。需要分开准备时，可先 `setup-dependencies.ps1 -SkipParserModels`，再运行 `setup-docling.ps1`。解析模型缓存保存在项目 `.tmp/models/`，清单记录文件哈希；`-Check` 校验存在性与完整性。CPU 路径为本机默认，首次下载与第一次加载的时间应分别观察。

平台知识服务使用后端统一配置，主要环境变量如下。凭据放在本机后端配置中，不写入知识节点、截图或交付文档。

后端默认读取启动目录的 `.env`，也支持 `ATLAS_ENV_FILE` 指定配置文件。修改配置后重启后端使其生效；代码默认值与本机已保存的有效配置可能不同，以空间模型提示和实际调用记录为准。

| 配置 | 作用与代码默认值 |
|---|---|
| `DASHSCOPE_API_KEY` | 平台模型凭据；为空时保留原文、结构图和已有内容 |
| `LLM_API_BASE` | OpenAI 兼容接口地址，默认 DashScope compatible-mode/v1 |
| `LLM_MODEL` | 统一模型名称，代码默认 `qwen3.8-flash`，以实际配置为准 |
| `KNOWLEDGE_MODEL_ENABLED` | 知识抽取、学习和比较开关，代码默认 true；仍需凭据且符合运行模式 |
| `KNOWLEDGE_USE_DOCLING` | 结构解析主路径开关，默认 true |
| `KNOWLEDGE_FORMULA_VISION_ENABLED` | 有预算时的公式图像补充，默认 true |
| `KNOWLEDGE_PARSER_TIMEOUT_SECONDS` | 独立解析进程超时，默认 1200 秒 |
| `RESEARCH_MODEL_MAX_REQUESTS` | 单份资料基础分析请求上限，默认 16 |
| `RESEARCH_MODEL_MAX_INPUT_CHARS` | 模型文本请求输入字符上限，默认 60000 |

新的 `KNOWLEDGE_MODEL_ENABLED` 与旧研究工作流的 `RESEARCH_MODEL_ENABLED` 分别控制各自服务，不应混为同一个开关。离线或多人运行模式会关闭本轮知识服务的付费模型路径；现有账号隔离保留，完整流程首先支持本机使用。工作台显示平台模型是否配置及是否启用，不要求每个知识节点单独配置密钥。

默认限制为 **基础分析 16 次、单次深入学习最多 4 次、模型并发 2、结构解析并发 1**。学习的一致性审阅包含在这 4 次内；比较采用最多 **8 次**的独立预算，支持四组生成与审阅。公式补充占用所属分析或学习预算。预算用尽保存已有内容为部分完成，可继续；不会自动无限重试。

每次模型调用记录模型、用途、成功/失败、耗时、供应商返回的 token 用量，并关联任务。缓存命中和读取页面不新增生成调用。这些是可检查的运行机制；实际费用、耗时及质量结果见验收记录，不能从请求上限推算保证值。

## 9. 旧数据迁移与恢复

迁移是增量离线导入，不调用模型、不追踪资料内链接，也不读取报告里提到的本机路径。已有原论文与保存段落可进入新来源和结构图；旧方法、实验设置、测量及可定位证据映射为历史知识，并保留旧审核状态与版本。无法核对的证据保留未验证信息，不伪造新原文定位。

先按[备份说明](local-data-recovery.md)备份数据库、原文件和配置，在独立副本验证，再对实际资料目录迁移。下面的占位目录必须替换为明确选定的副本路径；脚本不替用户创建备份。

```powershell
backend\.venv\Scripts\python.exe backend\scripts\migrate_knowledge_workspace.py --data-dir "D:\明确选定的资料副本"
```

仅迁移一个空间时：

```powershell
backend\.venv\Scripts\python.exe backend\scripts\migrate_knowledge_workspace.py --data-dir "D:\明确选定的资料副本" --project-id "实际空间ID"
```

脚本检查所选根目录及有效账号目录，拒绝链接目录，输出各作用域导入/跳过数量、警告与 `model_calls: 0`。重复执行复用迁移标识，已有新版来源及活跃任务受到保护。迁入的旧解析标为部分完成，可由用户在新资料页继续分析；这一步才可能按平台配置调用模型。

原始旧表、旧笔记与快照继续保留。迁移不将旧快照改写为新版结论，也不把历史人工记录重新标为模型核验成功。恢复时仍使用所备份的整套数据库与原文件，避免只恢复数据库而丢失证据文件。

## 10. 验收与交付边界

首轮真实任务覆盖指定四篇论文、原始研究报告及公开 CoorDex 固定代码快照。任务 A 需要明确比较论文与 D2，再进入证据返回；任务 B 需要沿状态门控或有界残差进入数学、前置知识、代码与演示，再返回。

前端构建、回归测试、桌面/手机、深浅主题与原文返回检查属于软件验证；抽取语义、公式识别、跨资料关系、实验条件与结果判断还需基于真实原文逐项检查。不同层面的结果分别记录在[本轮验收记录](validation/knowledge-workspace-2026-10-29.md)，不以页面可打开或测试通过代替论文质量验收。

本轮不包括公网正式部署、完整机器人训练/实验管理、任意节点自动生成实验或自动确认科研创新。个人源码和结果没有导入，相关依据仍以报告陈述与明确提供的公开资料为准。
