# Research Atlas 产品需求文档

## 1. 文档概述

### 1.1 产品名称

Research Atlas：科研知识图谱与个性化学习路径智能体平台。

### 1.2 产品定位

以知识图谱为底层，以科研学习路径为核心，以用户成长结果为评价标准的科研入门智能体平台。

平台面向科研新手，将论文、教材、课程、代码、数据集和实验资料组织为可追溯的科研知识网络，并根据用户的当前基础、研究目标和可投入时间，生成可执行、可验证、可动态调整的科研学习方案。

### 1.3 产品愿景

让科研新手不再面对“论文看不懂、资料太分散、不知道先学什么、读完不会做”的问题，而是能够获得一条从当前水平通往目标能力的清晰路径：

```text
上传资料 → 形成知识关系 → 找出前置知识 → 制定学习路线
→ 完成阅读/练习/复现任务 → 评估成长 → 动态调整路线
```

### 1.4 目标用户

首期聚焦具身智能、强化学习和相关机器学习方向的科研初学者，包括：

- 刚接触研究方向的本科生、研究生；
- 有编程基础但论文阅读经验不足的学习者；
- 想从课程学习过渡到论文阅读和实验复现的用户；
- 需要快速建立某个研究方向知识地图的用户。

后续可扩展至其他科研领域，但首期不追求通用化。

### 1.5 核心价值主张

平台不是单纯的论文搜索、摘要生成或聊天问答工具，而是帮助用户完成科研入门任务：

1. 解释论文讲了什么；
2. 识别用户还缺什么基础；
3. 说明应该先学什么、为什么；
4. 提供具体的论文、课程、代码和练习；
5. 追踪用户是否真正掌握；
6. 根据学习结果调整下一步计划。

## 2. 用户问题与产品目标

### 2.1 用户痛点

| 痛点 | 具体表现 |
|---|---|
| 不知道从哪里开始 | 搜索结果很多，但缺少前置关系和学习顺序 |
| 论文读不懂 | 概念、方法、公式、实验背景互相依赖 |
| 资料碎片化 | 论文、教材、代码、数据集分散在不同来源 |
| 无法判断重点 | 不知道论文中的核心贡献、关键实验和必学概念 |
| 学习难以坚持 | 没有明确任务、完成标准和反馈 |
| 读完不能实践 | 缺少复现、练习和小项目的衔接 |
| 不信任自动总结 | 无法知道结论来自哪篇论文、哪一段原文 |

### 2.2 产品目标

#### MVP 目标

用户上传 3—10 篇论文后，平台能够：

- 解析论文并提取核心实体、关系和证据；
- 构建用户可浏览的领域知识图谱；
- 识别目标论文或研究方向所需的前置知识；
- 根据用户基础和时间生成两周至三个月的学习路线；
- 将路线拆成论文阅读、知识学习、代码实践和复现任务；
- 支持用户勾选完成任务并保存进度。

#### 中期目标

- 根据测验和任务结果动态调整学习路线；
- 支持多来源资料融合和冲突说明；
- 支持论文间的方法、数据集、实验和引用关系分析；
- 形成可量化的用户成长档案。

#### 长期目标

- 从“科研入门”扩展到“研究问题发现”和“实验方案设计”；
- 形成领域化、持续更新的科研知识资产；
- 评估用户从阅读到复现、从复现到改进的科研能力成长。

## 3. 产品原则

### 3.1 结果优先

知识图谱是底层能力，不是最终展示目标。每个图谱功能都必须服务于学习理解、路线规划或科研任务执行。

### 3.2 证据优先

每个重要知识关系和学习建议都应该能够追溯到原始资料、页码或文本片段。系统应区分事实、推断和推荐。

### 3.3 小步可执行

计划必须拆成用户今天或本周能完成的任务，避免只输出大段建议。

### 3.4 允许不确定

证据不足、来源冲突或实体匹配不确定时，系统应提示用户确认或明确拒答，不生成确定性结论。

### 3.5 人机协作

LLM 负责理解、抽取和表达，图算法负责路径、依赖和排序，人工审核负责高影响关系的质量控制。

## 4. 产品信息架构

```text
首页 / 我的科研空间
├── 我的目标与能力画像
├── 学习路线与今日任务
├── 我的论文与资料
├── 论文学习卡片
├── 知识图谱
├── 审核工作台
├── 进度与成长报告
└── 设置与数据管理
```

## 5. 核心用户流程

### 5.1 新用户首次使用

1. 选择研究方向或输入自然语言目标；
2. 填写当前基础、已有知识、每周可投入时间；
3. 选择目标类型：读懂论文、掌握基础、复现实验、完成课程项目或寻找研究问题；
4. 上传论文、教材或资料链接；
5. 系统解析资料并展示处理状态；
6. 生成知识概览和初始学习路线；
7. 用户确认目标实体和路线偏好；
8. 进入今日任务和论文学习卡片。

### 5.2 上传论文后的流程

```text
上传 PDF
→ 文档解析
→ 章节和文本切分
→ 实体/关系/主张抽取
→ 实体对齐与候选审核
→ 写入知识图谱
→ 生成论文学习卡片
→ 更新个人学习路线
```

### 5.3 学习路线流程

```text
用户目标 + 当前能力 + 时间约束
→ 目标实体定位
→ 前置知识闭包
→ 学习顺序排序
→ 资料和论文推荐
→ 阅读/练习/复现任务生成
→ 用户完成任务
→ 测验/反馈
→ 更新掌握度和下一步路线
```

## 6. 核心功能需求

## 6.1 用户画像与科研目标

### 功能说明

建立用户的目标、基础、学习时间和偏好，作为路线生成的输入。

### 输入项

- 研究方向；
- 自然语言科研目标；
- 已掌握概念；
- 数学基础；
- 编程基础；
- 论文阅读经验；
- 每周可投入时间；
- 目标周期；
- 目标类型。

### 输出项

- 当前能力摘要；
- 目标能力节点；
- 初步知识缺口；
- 推荐学习路径；
- 路径生成依据。

### 验收标准

- 用户能在 3 分钟内完成首次画像；
- 用户可以使用自然语言描述目标；
- 目标无法准确映射时，系统展示 Top-K 候选并要求确认；
- 画像可以在后续路线生成前修改。

## 6.2 论文与学习资料管理

### 支持资料

- 本地 PDF；
- arXiv 论文；
- Semantic Scholar 元数据和引用信息；
- 教材、课程讲义和网页资料；
- GitHub 或官方代码链接；
- 数据集和实验资源。

### 资料元数据

- 标题、作者、年份、来源；
- 摘要和全文状态；
- DOI、arXiv ID 或外部链接；
- 代码、数据集和实验资源；
- 解析状态；
- 来源可信度；
- 版本和更新时间。

### 用户体验要求

- 上传后立即显示任务状态；
- 解析失败时说明原因和可操作的修复建议；
- 支持重新解析；
- 显示资料是否已进入图谱；
- 支持删除、归档和重新处理。

## 6.3 论文解析与知识抽取

### 抽取对象

首期实体类型：

- Paper；
- Concept；
- Method；
- Dataset；
- Benchmark；
- Resource；
- Author。

首期关系类型：

- CITES；
- PROPOSES；
- USES；
- EVALUATES_ON；
- IMPROVES_ON；
- COMPARED_WITH；
- PREREQUISITE_OF；
- HAS_RESOURCE；
- SUBTOPIC_OF。

### 每条知识必须保存

- 主体和客体；
- 关系类型；
- 原文证据；
- 文档 ID；
- 页码或段落位置；
- 抽取模型和版本；
- 抽取置信度；
- 审核状态；
- 创建和更新时间。

### 抽取策略

```text
规则/小模型处理高频简单关系
→ 领域 NER 处理实体
→ LLM 处理复杂关系、事件和跨段落语义
→ 置信度分级
→ 高影响关系人工审核
```

其中 `PREREQUISITE_OF` 关系直接影响学习路径，默认必须进入人工审核或高质量验证流程。

## 6.4 实体对齐与知识融合

### 目标

将“Graph Convolutional Network”“GCN”“图卷积网络”等表示合并为同一实体，同时避免把相似但不同的概念错误合并。

### 处理流程

1. 规范化名称；
2. 别名匹配；
3. 类型过滤；
4. embedding 相似度匹配；
5. 根据阈值分为自动合并、人工确认和新建；
6. 保存合并历史和来源。

### 质量要求

- 自动合并必须保留可撤销记录；
- 低置信度匹配不能直接入图；
- 同名实体必须展示候选上下文；
- 用户能够纠正实体名称和类型。

## 6.5 审核工作台

### 核心界面

```text
左侧：候选队列
中间：原文证据与抽取结果
右侧：图谱上下文、相似实体和操作按钮
```

### 支持操作

- 通过；
- 编辑后通过；
- 拒绝；
- 合并到已有实体；
- 标记需要复核；
- 查看审核历史；
- 批量审核低风险候选。

### 优先级

1. 前置关系；
2. 方法与问题关系；
3. 方法与数据集关系；
4. 普通引用和资源关系。

## 6.6 个人知识图谱

### 图谱视图

- 按实体类型着色；
- 搜索实体；
- 展开一跳或两跳邻域；
- 按论文、方法、概念、数据集过滤；
- 查看关系证据；
- 查看知识前置链；
- 查看用户掌握状态。

### 关键交互

用户点击一个概念后，系统应展示：

- 概念解释；
- 前置知识；
- 后续可学习内容；
- 相关论文；
- 相关实验；
- 容易混淆的概念；
- 用户当前掌握度。

图谱是学习导航的辅助工具，不应成为单独的炫技页面。

## 6.7 论文学习卡片

每篇论文解析完成后生成学习卡片，包括：

1. 一句话解释；
2. 解决的问题；
3. 核心方法；
4. 需要的前置知识；
5. 关键实验和结论；
6. 论文在知识图谱中的位置；
7. 推荐阅读顺序；
8. 重要原文证据；
9. 自测问题；
10. 阅读后的实践任务。

## 6.8 个性化科研学习路线

### 输入

- 用户目标；
- 当前掌握知识；
- 每周学习时间；
- 目标周期；
- 已上传资料；
- 代码和算力条件；
- 学习偏好。

### 路线算法

1. 将目标解析为知识图谱实体；
2. 计算 `PREREQUISITE_OF` 前置知识闭包；
3. 剪除用户已掌握节点；
4. 对剩余节点进行拓扑排序；
5. 为每个节点匹配论文、教材、课程和代码；
6. 按教学价值、难度、资源可获得性和时间成本排序；
7. 生成阶段化学习计划；
8. 绑定阅读、练习、复现和反思任务；
9. 用户反馈后重新计算路线。

### 推荐项结构

每个推荐项至少包含：

- 标题；
- 类型：论文/知识/实验/资源；
- 预计耗时；
- 难度；
- 前置条件；
- 完成标准；
- 推荐理由；
- 证据来源；
- 是否完成。

### 路线模板

```text
阶段目标
→ 必学知识
→ 推荐资料
→ 阅读任务
→ 练习任务
→ 实践/复现任务
→ 自测
→ 进入下一阶段的条件
```

## 6.9 学习任务与成长反馈

### 任务类型

- 阅读并总结；
- 概念解释；
- 公式推导；
- 代码实现；
- 实验复现；
- 结果对比；
- 研究笔记；
- 批判性问题。

### 完成标准

每个任务必须有可观察的完成结果，例如：

- 能用自己的话解释概念；
- 能画出模型流程；
- 能运行代码；
- 指标达到合理范围；
- 能说明实验失败原因；
- 能提出一个改进假设。

### 成长指标

- 已掌握知识节点数；
- 掌握前置链完整度；
- 已阅读论文数；
- 已完成实践任务数；
- 已复现实验数；
- 测验正确率；
- 目标能力覆盖度；
- 路线完成率。

## 6.10 可信回答与证据追溯

平台输出的每个重要结论应具备：

- 支持该结论的资料；
- 原文片段或页码；
- 证据强度；
- 是否存在反向证据；
- 信息更新时间。

回答生成采用两阶段：

```text
检索证据 → 生成结构化 claims → 逐条核验 → 生成自然语言回答
```

系统必须支持：

- 无证据时拒答；
- 来源冲突时并列展示；
- 信息可能过期时提醒；
- 区分论文事实与系统推荐；
- 点击回答跳转至原文证据。

### 7.1 核心节点

```text

  "valid_to": null

```

## 8. 非功能需求

### 性能

- 单篇论文上传后，用户可立即看到解析状态；
- 中小型论文在可接受时间内完成解析；
- 图谱局部查询目标延迟不超过 2 秒；
- 路线生成应显示实时进度或阶段状态；
- 检索结果必须支持分页和过滤。

### 可用性

- 首次用户不需要学习知识图谱术语；
- 所有复杂结果均提供“为什么”；
- 任务有明确的完成标准；
- 手机或窄屏场景下保证核心内容可阅读。

### 安全性

- 上传文件限制大小、类型和解析页数；
- 服务端生成资源 UID；
- 生产环境启用认证、权限和限流；
- LLM 密钥不写入前端和仓库；
- 日志不保存原始密钥和敏感用户数据。

### 可解释性

- 路线推荐必须展示图谱依据；
- 知识关系必须展示来源证据；
- 自动合并和自动通过可回滚；
- 推荐算法输出可复现。

## 9. 评测方案

### 数据集

建立 100—300 篇目标领域论文的标注集，至少包含：

- 实体标注；
- 关系标注；
- 前置知识关系；
- 方法—数据集关系；
- 论文事实问答；
- 学习路径合理性评测。

### 系统指标

| 指标 | 目标 |
|---|---|
| 实体 Precision/Recall/F1 | 分类型统计 |
| 关系 Precision/Recall/F1 | 特别关注前置关系 |
| 实体对齐准确率 | 自动合并单独统计 |
| 证据定位准确率 | 关系可回溯率接近 100% |
| 问答 Faithfulness | 高于普通 RAG 基线 |
| 引用正确率 | 关键结论逐条检查 |
| 路线专家评分 | 由导师/高年级学生盲评 |
| 任务完成率 | 观察真实用户使用结果 |
| 用户目标达成率 | 是否能读懂/复现目标论文 |

### 对比基线

1. LLM 直接回答；
2. 普通向量 RAG；
3. Hybrid RAG；
4. 仅知识图谱检索；
5. Research Atlas 个性化学习智能体。

## 11. 比赛展示方案

### 演示剧本

1. 新手输入目标：“三个月入门具身智能，并复现 Diffusion Policy”；
2. 上传目标论文和两篇基础论文；

9. 输入一个资料中不存在的结论，系统明确拒答；
10. 展示“普通 RAG vs 个性化路线”的对比结果。

### 比赛核心叙事

```text
普通工具回答“论文讲了什么”
Research Atlas 进一步回答“你现在该学什么，以及如何学会”
```

## 12. 成功标准

项目成功不以图谱节点数量为第一指标，而以以下结果为核心：

- 新用户能够在 10 分钟内得到一条可理解的学习路径；
- 用户能明确知道每一步学习任务和完成标准；
- 推荐内容与目标论文和用户基础匹配；
- 关键知识关系可追溯到资料证据；
- 用户完成学习任务后，系统能够更新路线；
- 真实用户能够更快读懂目标论文或跑通基础实验。
