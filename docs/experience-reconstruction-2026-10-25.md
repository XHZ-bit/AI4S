# PaperStride 研究空间体验：使用与迁移说明

更新日期：2026-10-25。本文说明本轮界面组织、工作上下文与兼容方式；实际浏览器检查、外部服务结果及未验证项另见 [验收记录](validation/experience-2026-10-25.md)。

## 从哪里开始

在仓库根目录使用现有启动脚本：

```powershell
.\start.ps1 -Mode Local -BackendPort 18000 -FrontendPort 15173
```

前端地址为 `http://127.0.0.1:15173/`，后端地址为 `http://127.0.0.1:18000/`。本轮后端接口改动需要重启服务才能生效；无需重新创建账号、导入论文或清空浏览器数据。

| 入口 | 主要用途 |
| --- | --- |
| 工作台 `/` | 继续上次工作、打开最近研究空间与资料、查看下一项行动 |
| 研究空间 `/research` | 按研究问题组织资料、比较、学习与成果 |
| 资料库 `/manage` | 默认浏览论文；通过“添加资料”“检索与发现”切换工作 |
| 探索 `/explore` | 切换文献关系与学习依赖，查看当前对象的详情 |
| 设置 `/settings` | 个人资料、模型与学习偏好 |
| 任务与行动 `/workflow` | 在“我的行动”和“系统处理”之间切换；后台任务链接进入 `?view=processing` |

工作台以“继续当前研究”和最近空间为主。有可恢复位置时，点击“继续上次任务”；初次使用可选“从论文开始”或“探索一个想法”。示例研究空间入口收在 Diffusion Policy 示例说明中。

## 用研究空间收拢工作

“新建研究空间”默认处于探索阶段，只需填写暂定名称。研究问题、验证目标、领域和资源条件可以之后补充；自定义领域允许暂时留空。若主动选择“已有明确问题”，仍需填写研究问题与首轮验证目标，保持正式验证流程的约束。

课题页面使用一条标题栏和五个视图：

| 视图 | 默认呈现与进一步操作 |
| --- | --- |
| 概览 | 当前问题、主要下一步、待解决问题与近期进展 |
| 阅读 | 关联论文选择与原文；“资料详情”中查看解析、元数据和重试入口 |
| 比较 | 默认打开证据整理表；下拉切换严格条件比较、资源推演和决策总览 |
| 实践 | 与课题相关的学习入口或 Diffusion Policy 实践；学习支持关闭时不显示常规实践入口 |
| 成果 | 默认笔记目录与编辑器；可切换研究计划、正式方案与冻结历史、变化解释、自动核查 |

版本、领域、刷新和学习开关位于“课题详情”。个人设置中关闭的学习功能不会被课题设置重新开启。非 Diffusion Policy 课题提供围绕自身问题的学习入口，不直接套用该示例。

从研究空间进入“添加资料”，可单篇或批量选择资料库中的论文；已加入的资料会显示对应状态。链接导入和 PDF 上传会继续关联到当前空间，关联失败可单独重试，无需重新上传。阅读链接直接打开当前空间的阅读视图。

## 阅读、解释与笔记

独立论文页 `/papers/{uid}` 与课题“阅读”视图共用论文内容组件。原文作为主体，资料处理工具收在“资料详情”，辅助面板默认收起。

1. 在可选择文字的 PDF 正文中选择一段文字。
2. 选文附近出现“解释”“记笔记”“存为问题”。“解释”遵循用户是否开启论文辅导的偏好。
3. 点击操作后，在当前页面打开对应辅助面板。选文、论文及页码随操作传递。
4. 辅导以当前问题为起点；深入课程时按解释、可视化、检查题或代码练习逐项展开。可以跳过已懂环节。
5. 从学习页的“返回刚才的阅读”回到携带上下文的入口。笔记和问题保存在现有记录系统，课题“成果”也能打开同一记录。

文本选择依赖 PDF 的文字层；纯扫描页需要先获得可选择文本。未形成可核对文档定位的内容不会因此变成已核验的论文证据。

笔记保存有版本冲突保护。切换记录后，较早发出的保存响应不会替换当前编辑器；编辑草稿恢复包含正文与来源信息，不把草稿序列化内容显示为笔记正文。出现同步错误时可继续保留本地输入，并使用页面重试入口。

## 探索与学习的呈现

文献关系提供种子论文、前向/后向引用查询和探索返回入口；列表、图谱与详情围绕当前选择呈现。数据集等对象的资源链接、关系来源及候选状态集中在对象详情。学习依赖单独切换，表达建议先理解的知识，不把引用关系等同于先修关系。

课程页面以章节目录和当前问题为主，示例、背景与学习记录按需展开。基础课活动包括 `explain`、`visual`、`quiz`、`code`；Diffusion Policy 单元还包括 `reflect`。被关闭的活动不会因旧链接而强行开启，而是选择当前可用的活动。浏览器练习与真实论文复现仍有明确区别。

搜索和输入使用统一的柔和边界，保留键盘焦点；正文控制行宽，表格和代码在自己的容器内横向滚动。辅助栏适配宽屏与抽屉呈现。具体尺寸、主题和键盘流程的实测范围请查看验收记录。

## 连续操作与来源约定

前端使用 `frontend/src/api/workContext.ts` 共享导航字段：

`project`、`paper`、`page`、`ref`、`focus`、`session`、`lesson`、`step`、`activity`、`unit`、`document_id`、`document_version`、`returnTo`。

明确链接参数优先于自动恢复的工作现场。新选文会清除上一问题的会话与步骤，避免沿用错误上下文；辅导创建会话后更新地址，不应关闭当前面板或清掉选文。新增本地工作状态采用 `paperstride:{账号或local}:...` 命名，既有存储键继续保留。

`returnTo` 仅接受应用内路径，不接受外部网站、协议相对地址、反斜杠或控制字符；前端还去除嵌套 `returnTo`。返回位置因此用于恢复工作，不作为任意跳转地址。

### 工作现场接口

继续使用 `GET/POST /api/workbench/projects/{id}/scene`，保存仍需提交当前 `version`。版本不一致返回 HTTP 409，界面允许保留当前位置或恢复另一设备位置。

在已有 `view`、`paper`、`page`、`panel` 基础上，新增可选字段：

| 字段 | 约束或含义 |
| --- | --- |
| `ref`、`focus` | 原文引用与当前焦点，最长 250 字符 |
| `session`、`lesson`、`unit` | 会话、课程、单元标识，最长 100 字符 |
| `step` | 0–1000，允许第 0 步 |
| `activity` | `explain`、`visual`、`quiz`、`code`、`reflect` |
| `returnTo` | 安全应用内地址，最长 4000 字符 |
| `document_id`、`document_version` | 文档与内容版本，最长 150 字符 |
| `selection` | `{document_id, document_version?, page, quote}` |

选文页码为 1–10000，文字长度为 1–8000，不能仅为空白。服务端检查课题、关联论文、文档归属和版本；解析结果具有可靠总页数时，再校验实际页码上限。旧记录不需要补齐新增字段即可读取。

### 辅导与记录接口

现有辅导请求新增可选 `source_context`，结构同上述 `selection`。服务端先验证文档属于当前账号的指定论文，再在指定页查找原文片段：

- `matched_passage`：原文中找到文本匹配，附上对应片段定位；这只表示文字对应，不等于内容已通过科学审核。
- `user_selection`：未匹配到保存片段，保留为用户选文，不标成已核验的原文证据。

同一会话后续提问可沿用保存的来源快照；新选文则明确替换旧来源。进入阅读页或打开面板不会自动提交整篇付费辅导，生成仍由用户明确操作触发。

现有记录请求新增可选 `document_id`、`document_version`、`passage_id`。旧客户端只修改标题或正文时保留原有来源；明确切换论文时不携带上一论文的定位。所有记录仍使用现有 `workspace_records`，没有新建第二套笔记系统。

辅导成功响应提供可选 `timings.model_seconds` 与 `timings.total_seconds`：前者是服务端计时的辅导生成阶段，包含模型请求及响应解析；后者是本次请求总时长。生成时长随会话保存并可重新读取；旧会话没有计时数据时不补造数值，总时长仅本次实时响应提供。它们不是模型供应商内部计算时间，也不能据此承诺下一次请求速度。

## 兼容与迁移

本轮不重命名数据库、不替换旧账号、不全局改写浏览器存储键，也不重建论文、学习或笔记数据。新增工作现场、来源和计时信息使用现有 JSON 数据保存，既有初始化/增量建表逻辑继续幂等执行，无需数据破坏性迁移。

旧独立论文、课程、图谱、任务和行动链接仍保留。课题旧视图在页面内兼容映射，并保留其余查询参数：

| 旧 `tab` | 当前位置 |
| --- | --- |
| `workbench` | 默认概览；带 `record` 时进入成果中的对应记录 |
| `evidence` | 阅读，并展开方法与实验事实核对 |
| `scenarios` | 比较中的资源条件推演 |
| `plans` | 成果中的正式方案与冻结历史 |
| `changes`、`audit` | 成果中的变化解释、自动核查 |
| `radar` | 课题探索入口 |

### 升级前备份

本轮备份位于仓库的 `.local-backups/experience-20261025-132041/`，保留一个根数据库和七个账号数据库的相对目录。已使用 SQLite 只读连接分别执行 `PRAGMA quick_check`，**8 个数据库均返回 `ok`**。

该检查验证备份数据库的结构完整性；不代表 PDF 等文件已包含在数据库备份中，也不代表已执行真实账号数据回滚。

需要回滚时，先停止前后端及后台写入进程，另外备份当前数据库和相关文件，再把该备份对应的数据库恢复到原相对位置，并核对 SQLite 的 WAL/SHM 状态后启动兼容代码。不要在服务仍写入时覆盖数据库。本轮没有执行覆盖用户数据的恢复操作。
