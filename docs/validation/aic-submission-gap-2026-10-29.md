## 4. AI与开源融合：报告重点

评分分配为：问题与场景15、创新与设计20、AI与开源融合20、完成度及可验证效果25、开放复用15、材料表达5。完成度/可验证效果权重最高，同分时也优先比较该项。依据规则附件第4—5页。

本项目可以围绕真实问题建立证据链：结构解析提供有页码和区域的原文块，AI抽取带来源的研究知识，空间独立版本保存用户修订，图谱连接方法比较与知识学习，浏览器实践留下可检查产物。应清楚展示团队负责的数据契约、来源版本约束、上下文检索、比较与学习编排及故障处理，避免只列React/FastAPI等普通开发工具来证明“开源融合”。

| 评分方向 | 可用证据 | 当前风险 |
| --- | --- | --- |
| 场景价值 | 用户真实研究报告与反复反馈，四篇论文和个人方法比较任务 | 不能据此称为多人用户研究或普遍收益证明 |
| 创新设计 | 空间独立知识、原文依据、修订与历史、比较—学习—代码的闭环 | 旧报告/视频若只展示阅读器和通用聊天，难体现实质改进 |
| AI与开源 | Docling文档AI、公式模型、PDF.js、Pyodide与业务知识链融合 | 核心模型与新增依赖许可清单不完整；外部Qwen API不能等同于分发开源权重 |
| 可验证效果 | 真实资料端到端任务、失败样例、独立目录回归、用量记录 | 深讲质量、干净安装和最终提交版本需要本轮证据，不能由旧测试数量代替 |
| 开放复用 | 源码、契约、回归与原创练习可形成实质成果 | 远程版本滞后、顶层授权未定、最终访问链接未冻结 |
| 材料表达 | 已有23页报告与资源附录底稿 | 空字段、旧截图、旧模型配置和未录成片需更新 |

不预测评委分数，也不要求临时训练新模型或追求大规模数据。提交前优先让一个真实任务完整、可复查地运行。

## 6. 提交前冻结顺序

1. 确认报名、队伍编号、申报方向及收费状态；填写报告封面。
2. 完成一个真实论文＋个人方法的比较、深入学习与练习流程，保存准确日期和证据。
3. 从当前源码生成不含凭据/个人资料的交付包，在独立目录检查安装、启动与最短操作流程。
4. 更新第三方清单、AI辅助披露、权属和受限提交/开放计划；由团队完成最终人工复核。
5. 录制3—5分钟MP4，展示真实操作及开放成果入口；检查匿名信息。
6. 导出最终PDF，检查文件大小、空字段、过期截图、断链和学校/教师信息；记录交付包版本与哈希。
7. 将最终成果链接填入报名系统指定栏目，逐个打开验证权限；预留上传时间。最终提交由队长在后台确认，本次审计没有执行提交。
