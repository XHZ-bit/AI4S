# 无人工参与的迭代方案

## 目标与边界

由系统自动准备固定版本资料、生成候选关系、检查证据、比较画像路线、执行回归和故障注入、保留通过的工程改动。所有机器检查结果必须标为“自动核查”。原文精确匹配、关系结构合法和路线有差异，均不能证明教学判断正确或学习效果提升。

## 每轮闭环

1. **固定输入**：记录论文版本、PDF 哈希、代码版本、规则版本、运行环境和画像。缺失或哈希变化时停止。
2. **提出候选**：一次只改变一条抽取、排序或路线规则，并记录变更理由。候选先写隔离数据目录。
3. **自动反证**：检查引文精确位置、文档归属、关系端点、先修环路、证据缺失、撤回后的路线失效。加入故障注入，确认错误会被拒绝。
4. **对照评估**：与固定清单和上一版本比较证据覆盖、错误拒绝率、路线差异、耗时和失败数。评测题与当前生成器分离，不能让算法自己生成标准答案。
5. **保留或回退**：预设门槛全部通过且关键指标改善才保留；出现无证据推荐、错误关系被接受或回归失败，立即回退。报告保留原始结果，不填造效果值。

## 当前已落地

- `prepare_second_demo.py` 校验三个 PDF 的固定哈希，并从本地原文提取短引文。
- `auto_evaluate.py` 检查关系结构、原文偏移、来源归属、先修环路和两类画像的路线差异；输出 `auto-evaluation.json`，失败即停止。
- 演示页标记“自动核查预览”，正式路线接口不会误收录这些候选。

## 后续顺序

1. 扩大故障注入测试，覆盖错误引文、错配论文、关系环路和资料撤回。
2. 加入独立的固定对照任务与上一版本比较，并在报告中展示原始输出。
3. 设计可持久化的“机器核查路线”证据级别，与人工核验路线分开展示；自动路线必须附带检查范围与局限。
4. 将上述检查放入持续集成；每次变更生成版本化报告，再决定保留或回退。

该方案不安排专家审核或用户试验作为执行依赖。因此它能证明软件行为、证据定位和抗错误能力，不能据此宣称真实学习收益、领域正确率或机器人策略性能。
