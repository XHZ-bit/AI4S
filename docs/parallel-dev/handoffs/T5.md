## 实现内容

### AtlasV2 投影

- `build_graph_projection(snapshot)` 只读取 T1 传入的不可变 `ProjectSnapshot`，不打开或修改 SQLite。
- Neo4j 使用独立标签 `AtlasV2`、`AtlasV2Projection`、`AtlasV2Node` 和独立关系类型
  `ATLAS_V2_REL`；不匹配、覆盖或删除旧 `Entity` 节点/关系。
- Neo4j 内部稳定 UID 为
  `{project_id}:{snapshot_id}:{business_node_id}`，天然隔离项目和快照版本。
- 决策、方案、方法、实验设置、测量、证据、证据主张、方案步骤和冻结文档分别建模。
- 业务节点 ID 规则：决策、方案、方法、实验设置、测量、证据和未知类型事实使用原业务 ID；内部节点使用
  `project:`、`snapshot:`、`claim:{fact_id}:v{version}`、`planstep:` 和 `document:` 前缀。
- 同一方法的不同实验设置各自保留独立节点，通过
  `method -[HAS_SETTING]-> experiment_setting` 连接。
- 关系方向统一为“成果/容器指向其显式依赖”：例如
  `decision -[GOVERNS_PLAN]-> plan`、`plan -[RELIES_ON_CLAIM]-> evidence_claim`、
  `plan_step -[CITES_EVIDENCE]-> evidence`。影响查询沿这些边反向遍历。
- 所有关系保留 `fact_ids[]`、`evidence_ids[]`，并在返回时附加可解释的 `path` 与
  `explanation`；未沿用旧图的单一 `knowledge_id/passage_id`。
- 当前公共快照没有内嵌完整事实和证据内容。实现只分类方案中角色明确的 ID；其余冻结事实保留为
  `fact`，并标记 `classification=unknown_from_snapshot_reference`，不猜测类型、测量归属或来源。

### 幂等同步、版本发布和故障安全

- 投影状态为 `building | complete | failed`，并使用每次尝试唯一 `sync_token`。
- 同一 `project_id + snapshot_id + snapshot_version` 和相同内容摘要重复同步直接返回已发布计数，不重复写图。
- 同一不可变快照 ID 若出现不同版本或不同内容摘要，抛出 `ProjectionConflictError`。
- 重试只清理精确 `projection_key` 下的 AtlasV2 节点；没有全库删除，也不清理其他项目或历史快照。
- 写节点/关系时必须同时匹配当前 `sync_token`；同一快照的旧尝试不能在新重试后继续发布。
- 发布时才把 marker 原子切到 `complete`。存在更高 `snapshot_version` 时，晚到的旧版本可成为可查询历史版本，
  但 `current=false`，不能覆盖新版本。
- 同步中断把该投影标为 `failed/current=false`；T1 继续在 SQLite outbox 保存失败和重试状态，已保存业务成果不回滚。
- 查询同时要求 T1 outbox 为 `succeeded`（T1 已实现）且 Neo4j marker 为 `complete`；半完成/失败投影明确报错。
- 懒创建 AtlasV2 专用唯一约束：`projection_key` 和节点 `uid`。未修改旧图约束。

### 三类查询

三个入口均返回冻结的 `GraphQueryResult`，并通过 `GraphQueryResult.model_validate` 契约测试：

1. `query_dependencies(project_id, snapshot_id, node_id, limit=200)`：决策/方案到显式事实、证据和来源的依据路径。
2. `query_method_context(project_id, snapshot_id, method_id, limit=200)`：方法下明确关联的多个实验设置、测量、
   主张与来源路径。
3. `query_impact(project_id, snapshot_id, changed_evidence_id, limit=200)`：从指定证据或主张反向查找显式依赖的
   决策和方案；不调用模型，不推断隐含影响。

T1 当前已通过 `query_project_graph(query)` 接入同等模式：

- `kinds=["dependency_path"] + node_ids=[decision_or_plan_id]`
- `kinds=["method_context"] + node_ids=[method_id]`
- `kinds=["impact_path"] + node_ids=[evidence_or_claim_id]`

返回中的 `projection_status` 节点固定包含：

- `status` / `sync_status`
- `requested_snapshot_id`
- `actual_snapshot_id`
- `actual_snapshot_version`
- `current`

受影响成果列表在当前冻结模型中表示为结果 `nodes` 内 `kind=decision|plan` 的节点；关系路径为结果 `edges`，
每条边含稳定 `source_id/target_id/kind` 以及 `properties.path`。证据节点在详情可用时通过
`properties.detail_ref` 和 `properties.locator_json` 供 T4 打开证据详情。

## 给 T1 的接入说明

当前共享工作区中的 T1 已完成以下接线，本轮联合回归通过：

- `service.query_graph(conn, GraphQuery)` 先验证项目、快照和 SQLite outbox 状态，再调用 T5。
- `GET /api/projects/{project_id}/graph` 接收 `snapshot_id/node_ids/kinds/limit`。
- 路径模式缺少 `node_ids` 时返回校验失败；T5 返回项目/快照不匹配时 T1 拒绝响应。

错误处理：

- Neo4j 连接失败、marker 不存在、状态不是 `complete` 或投影超过首版完整路径读取安全上限时，T5 抛出
  `RuntimeError`；T1 转成 `CapabilityUnavailable(graph_query, temporary=True)`，API 应返回
  `503 graph_unavailable`。
- 路径模式缺少锚点由 T1 返回 `422 validation_error`。
- 项目或快照不存在由 T1 返回 404。
- 图查询失败不删除或修改 SQLite 成果；比较和导出仍按冻结契约读取 SQLite。

## 接口或公共文件变更申请

### 1. 快照内容不足，无法生成完整证据详情图

当前 `ProjectSnapshot` 只有 `frozen_facts: VersionRef[]`、`frozen_decision: VersionRef`、方案和文档引用，
没有冻结事实实体、`FieldEvidence`、`EvidenceRef` 或决策正文。仅凭 ID 无法可靠生成：

- 方法/设置/测量的名称、状态和来源；
- 设置到测量的归属边；
- 主张到证据、证据到文档的关系；
- `EvidenceLocator` 的页码、段落、表格行列；
- 决策自身的 `evidence_ids`。

建议 T0 冻结一个 `GraphProjectionInput` 公共模型，字段精确包含：`snapshot: ProjectSnapshot`、
`decision: ResearchDecision`、`methods: list[MethodCard]`、`experiment_settings: list[ExperimentSetting]`、
`measurements: list[Measurement]`、`evidence: list[EvidenceRef]`。T1 从同一 SQLite 事务可见的冻结版本组装后传给 T5；
T5 仍不得自行读取数据库。兼容方式是保留现有 `build_graph_projection(snapshot)`，新增接收完整输入的冻结入口，
旧入口继续生成“不猜测类型”的最小投影。

建议测试：事实版本精确匹配、跨项目引用拒绝、证据 locator 保真、多来源同字段保留为不同证据、同方法多设置及
各自测量不串线、撤回证据仅影响显式依赖成果。

### 2. `GraphQueryResult` 缺少专用查询元数据

当前冻结返回仅有 `project_id/snapshot_id/nodes/edges`，没有顶层 `requested_revision`、
`actual_revision`、`sync_status`、`paths` 或 `affected_results`。T5 为保持公共模型合法，暂时把同步元数据放在
`kind=projection_status` 的合法 `GraphNode`，路径放在 `GraphEdge.properties.path`，受影响成果由节点类型表达。

建议 T0 后续在保持 `nodes/edges` 兼容的前提下冻结：

- `GraphQueryMode = dependency_path | method_context | impact_path | subgraph`；
- 查询的 `anchor_ids`（或正式确认继续使用 `node_ids`）与 `requested_revision`；
- 响应的 `actual_revision`、`sync_status`、`current`、`paths`、`affected_result_ids`。

字段正式冻结前，T5 不会在私有模块另造一套响应 Pydantic 模型。
