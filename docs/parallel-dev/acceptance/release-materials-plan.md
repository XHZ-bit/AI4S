# Research Atlas 发布材料准备计划

日期：2026-10-04。执行窗口：2026-10-10—2026-10-14。基础契约：`research-v1.1`。

本计划用于内部发布验收、报告、PPT 和演示视频准备，不代表授权公开仓库、部署公网、购买资源或提交比赛材料。材料制作期间不得调用未获授权的真实模型服务，不得下载论文、训练数据或模型权重，不得把 mock、合成夹具或 jsdom 结果描述成真实服务、真实论文效果或浏览器 PDF 验收。

## 1. 材料统一口径

### 1.1 当前可陈述状态

- 核心代码可冻结：课题、论文关联、候选抽取、人工确认、条件比较、人工决策、人工方案编辑、保存、不可变快照与 JSON/Markdown 导出已有实现和自动化证据。
- 无方案生成 provider 时，生成任务明确失败；用户仍可从 `user_input` 人工空白草稿完成保存、快照和导出。
- SQLite 是业务事实真源；Neo4j 是可重建投影。图服务失败不得回滚已保存快照。
- 自动化门禁记录为：Research 后端 106 项、旧后端 116 项、前端全量 33 项、打印页 jsdom 2 项、静态门禁 11/11、前端生产构建成功。
- 上述测试使用临时 SQLite、模拟模型或模拟图服务；它们不是实时外部服务或真实论文效果验证。

### 1.2 材料中的证据等级

所有结论必须带以下一种状态，不得省略：

| 标签 | 含义 | 可使用的表述 |
|---|---|---|
| `已实现` | 源码和接口已经存在 | “平台支持……” |
| `自动化已验证` | 有可复跑的测试命令和记录，可能使用 mock | “在临时数据库和模拟服务下通过……” |
| `人工已验证` | 有日期、环境、操作者、截图或文件哈希 | “在指定浏览器/环境人工完成……” |
| `真实服务已验证` | 有明确授权、隔离环境和真实服务日志 | “在该版本和该服务配置下完成……” |
| `未验证` | 当前没有相应证据 | “尚未验证，不能据此推断……” |
| `受阻` | 缺少授权、人员或环境 | “等待……后执行” |

报告、PPT、视频中的数字必须可回指具体命令记录、人工验收记录或人类评测数据。合成评分器的 `0.5` 只用于验证评分器，禁止作为产品指标。

## 2. 总报告结构

按负责人提供的 AIC·AI+开源竞赛要求：技术报告正文建议 15 页以内，PDF 不超过 10MB。
长表、原始测试日志与补充证据独立整理；不得靠无限追加附录规避材料限制。
视频为 MP4、3—5 分钟、不超过 300MB；作品名不超过 20 字，简介不超过 300 字。
简介按“问题—方案—实现—效果—开放成果”组织；成果访问链接需覆盖评审期，但公开发布仍须单独授权。

1. **执行摘要**
   - 要解决的问题：单篇阅读难以支持跨论文科研路线决策。
   - 当前交付：知识图谱驱动、证据可追踪、人工可控的首轮验证方案工作台。
   - 状态结论：核心代码可冻结；真实服务、浏览器 PDF 和人类效果评测按实际状态单列。
2. **用户问题与首版边界**
   - 完整流程和 P0 功能。
   - 明确不做自主科研、自动复现、训练、自动论文写作、跨协议排行榜。
3. **产品流程与交互**
   - 建课题、关联资料、抽取、确认、比较、决策、人工/模型方案、快照、导出、历史复核。
   - 对应截图使用 S01—S15 编号，见第 6 节。
4. **数据和科学语义设计**
   - 方法、实验设置、测量分离。
   - `literature_report`、`user_input`、`model_suggestion` 来源分离。
   - `unknown`、`not_found`、`not_parsed`、`conflicting`、`reported` 的区别。
   - 不同数据集、划分、协议和指标范围不可直接排序。
5. **架构与可靠性**
   - React / FastAPI / SQLite / Neo4j 的职责边界。
   - 异步任务、重启中断、409 乐观锁、图失败保留与重试。
   - 快照冻结引用和 `needs_review` 影响检测。
6. **两个领域配置**
   - 图像异常检测的比较维度和指标范围。
   - 时间序列预测的预测窗口、频率、划分、目标范围等比较维度。
   - 说明领域配置是比较规则，不是预置论文答案。
7. **验证方法和结果**
   - 自动化门禁及完整命令。
   - mock、静态门禁、jsdom、浏览器人工、真实服务、人类评测分别成表。
   - 不仅列成功，还列 409、模型失败、图服务失败、重试和数据保留证据。
8. **效果评测设计**
   - 人工 gold、同领域 holdout、跨领域迁移和 A/B/C 对照方案。
   - 若 10—14 日只完成小规模 pilot，必须标为探索性，不做显著性或普适性结论。
9. **来源、许可、隐私与安全**
   - 论文只保存元数据和链接的默认策略。
   - Diffusion Policy 固定源码教学案例的 MIT 许可与自主开发边界。
   - 依赖、字体、图标、音乐、截图、人物声音和数据授权清单。
10. **限制、风险与下一步**
    - 未验证项、授权阻断、单机和非权限系统边界。
    - 真实服务接入、领域核验、浏览器验收和外部试用路线。

附录至少包括：API/契约版本、测试命令与原始摘要、截图索引、构建标识、人工验收表、许可登记表、术语表和禁止宣称清单。

| 2 | 为什么单篇阅读不够 | 方法、条件、指标和决策散落，跨协议数字容易误比较 | 自绘“论文→事实→决策→方案”流程图 | T0 |

## 4. 3—5 分钟视频分镜与旁白提纲

目标时长约 4 分 20 秒。默认使用团队原创合成演示资料或已获书面授权资料；画面不得出现密钥、`.env`、真实用户目录、私人论文全文或未脱敏日志。

| 时间 | 画面/操作 | 旁白要点 | 证据边界 |
|---|---|---|---|
| 0:00—0:20 | 标题和九步流程动画 | “Research Atlas 把多篇论文中的方法、实验条件和证据组织为可复核的科研方案。” | 定位陈述，不宣称效果 |
| 0:20—0:50 | 创建图像异常检测课题，填写项目约束 | 强调项目版本、约束版本和用户输入来源 | S02 |
| 0:50—1:20 | 关联两份原创合成资料，启动候选抽取 | 文本和表格候选都保留定位；抽取结果仍是候选 | S03—S04；若用 mock，画面角标持续显示“模拟模型” |
| 1:20—1:55 | 查看方法卡、两个实验设置、测量和未知字段 | 同名方法可有多个设置；未找到、未解析、冲突不会被补成事实 | S05—S06 |
| 1:55—2:25 | 打开条件比较，展示不可比原因 | 平台按数据集、划分、协议和指标范围分组，不做跨组排行榜 | S07 |
| 2:25—2:50 | 人工确认候选并保存路线决策 | 用户选择而不是系统自动替用户决定 | S08 |
| 2:50—3:25 | 展示 provider 不可用的明确失败，切换到人工空白方案并编辑 | 无模型时已保存内容仍可读；人工方案固定标为 `user_input` | S09—S10 |
| 3:25—3:50 | 保存方案、创建不可变快照、下载 JSON/Markdown | 快照冻结论文、事实、决策和约束版本，依据可追踪 | S11、S14 |
| 3:50—4:10 | 修改证据状态，旧快照变为 `needs_review`；展示图投影重试 | 失败不删除原始资料或历史方案，受影响成果可被发现 | S12—S13 |
| 4:10—4:20 | 状态页或结尾卡 | “核心代码门禁已通过；真实服务、浏览器 PDF 和人类效果评测按实际完成情况报告。” | 禁止说“全部发布验收完成” |

录制要求：

- 每个关键点击停留 1—2 秒，状态标签和证据定位必须可读。
- 若镜头使用测试环境，左上角常驻“临时数据库 / 合成资料 / 模拟服务”标识。
- 不剪掉失败状态后伪装无缝成功；重试必须显示旧任务失败和新任务 ID。
- 旁白稿中的数字在录制前与最终测试记录核对；测试数量变化时同步字幕、报告和 PPT。
- 配乐、字体、图标和录音素材必须进入许可清单；没有明确许可就不使用。

## 5. 演示步骤与验收记录

### 5.1 演示前准备

1. 冻结演示构建，记录源码恢复包 SHA-256、`research-v1.1`、浏览器版本、操作系统、时间和操作者。
2. 将 `DATA_DIR` 指向新的临时目录；确认不连接用户正在使用的数据库或 Docker 数据卷。
3. 准备两份团队原创的合成资料：一份包含两个实验设置和表格，一份包含缺失/冲突字段；资料页眉标明“合成演示材料，不代表论文结果”。
4. 选择演示模式：
   - 默认模式：无真实模型，明确展示失败和人工方案流程；
   - 受权模式：仅在字段范围、服务、日志脱敏和数据保留已签字后使用真实 provider。
5. 检查截图目录不包含 `.env`、密钥、个人路径、私人资料、真实用户名或未脱敏请求体。

### 5.2 主演示流程

1. 打开 `/research`，创建课题并填写领域、研究问题和资源约束。
2. 关联两份资料，核对冻结的文档 ID、版本和哈希。
3. 启动候选抽取；若模型未授权，演示环境可使用明确标识的模拟服务，但视频和报告必须标注。
4. 查看方法、实验设置、测量和字段证据，指出来源类型与查找状态。
5. 人工确认一条候选，将另一条标为争议，保留理由和版本。
6. 发起条件比较，证明不同划分/协议/指标范围不进入同一排名。
7. 保存路线决策，核对考虑过的候选、选择理由和冻结版本。
8. 请求模型方案生成并展示未授权 provider 的明确失败；验证既有项目和历史仍可读取。
9. 创建人工空白草稿，填写目标、步骤、输入、验收条件、风险和未知项；不填写虚构成绩、显存或耗时。
10. 保存方案，创建不可变快照，下载 JSON 和 Markdown；核对来源、项目/约束/事实/决策/文档版本。
11. 打开打印页，在支持浏览器中打印为 PDF；逐页检查分页、字体、链接、未知项和 `needs_review` 状态，并记录 PDF SHA-256。
12. 模拟图服务不可用，确认快照仍存在；恢复后点击重试，核对新旧任务 ID。
13. 修改被引用事实或项目约束，确认旧快照变为 `needs_review`，内容本身没有被静默改写。
14. 使用旧论文学习工作台和 Diffusion Policy 固定案例做快速回归，证明旧入口和记录仍保留。

每一步记录：时间、操作者、环境、预期、实际结果、证据编号、是否通过、缺陷 ID。若任一步失败，保留失败截图和日志摘要，不重录成“从未失败”。

## 8. 禁止宣称事项

以下表述在获得对应证据前禁止出现在报告、PPT、视频、新闻稿或答辩中：

- “发布完成”“生产就绪”“真实端到端全部通过”。当前只有核心代码和自动化门禁达到冻结条件。
- “真实模型、Neo4j、GROBID 或断网恢复已验证”，除非有受权环境的独立记录。
- “PDF 导出已验证”，除非实际浏览器打印、逐页检查并记录 PDF 哈希；jsdom 只验证页面状态文字。
- “达到 95% 准确率”“显著提升效率/质量”“优于通用助手”或任何未由完整人工 gold/A/B/C 数据支持的指标。
- 把合成评分器的 `0.5`、mock 测试、静态门禁或测试通过数解释为科研质量、抽取准确率或用户效果。
- “自动判断科学结论正确”“自主科研”“自动复现”“自动训练”“自动论文写作”。
- “知识图谱是事实真源”。SQLite 才是业务事实真源，图谱只是可重建投影。
- “来源可定位即结论正确”“表格数值已经验证”“未找到等于论文未报告”。
- “系统会自动选定最佳方法”或把不可比条件下的数字组成排行榜。
- “阅读完成等于掌握”“实验记录等于论文结果复现”“代码检查等于模型复现”。
- “支持多用户权限隔离”。当前导航分流不构成权限系统。
- “覆盖所有科研领域”。当前只冻结图像异常检测和时间序列预测两个领域配置。
- “公开访问即可自由再分发论文/图片/数据/代码”。每类资产必须分别核对许可。
- 暗示外部论文作者、上游项目、模型服务商或数据集维护者认可或背书 Research Atlas。
