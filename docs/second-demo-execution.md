# 第二个体验案例：同目标、不同基础的可追溯学习路线

状态：2026-10-09 已完成可运行的自动核查预览；自动检查覆盖结构、原文定位、来源归属、环路与画像差异。教学有效性尚未证实。

## 为什么选这一案例

保留原有 Diffusion Policy 源码交互案例，第二个案例仍围绕同一具身智能目标。学习者 A 已了解模仿学习，学习者 B 已了解扩散模型。两人使用相同的目标与规划算法，仅改变“已掌握概念”，展示不同的待学先修阶段，并可逐项打开论文原文。这样直接展示平台的资料、知识关系、画像、路线和证据定位能力。

## 固定资料与许可边界

| 用途 | 资料 | 固定版本 | 本地 PDF SHA-256 |
|---|---|---|---|
| 机器人示教背景 | [RoboMimic 论文](https://arxiv.org/abs/2108.03298v2) | 2108.03298v2 | `18283ff9cbb9645de4ccf32ca2de472f452e89761287e7ed578e3a1066bea5f1` |
| 扩散模型背景 | [DDPM 论文](https://arxiv.org/abs/2006.11239v2) | 2006.11239v2 | `aee5e07a802e8dfd2a386374c94fd61d1d056cb7e1e0fec4f28e8120ff5d8505` |
| 共同目标 | [Diffusion Policy 论文](https://arxiv.org/abs/2303.04137v4) | 2303.04137v4 | `75a57946e2cef790775ca5c667b00befc8ea7d64c3a02c5ced3e3d173354640c` |

脚本只把 PDF 下载到指定的本地数据目录；仓库不收录论文 PDF、图片或长段原文。原有官方源码专题保持既定上游版本和 MIT 许可说明。论文里的文字只用于本地证据定位；两条“先修”关系属于教学顺序假设，不能当作论文作者的明确结论。

## 准备与运行

在仓库根目录新开 PowerShell，选择一个**全新空目录**：

```powershell
python backend/scripts/prepare_second_demo.py --data-dir .tmp/second-demo-review
$env:DATA_DIR = (Resolve-Path .tmp/second-demo-review).Path
cd backend
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

在第二个 PowerShell 窗口运行：

```powershell
cd frontend
npm run dev
```

打开 `http://127.0.0.1:5173/demo/personalized-roadmap`。切换任一学习者的“已掌握概念”，路线会重新计算；“原文依据”可打开 PDF 解析段落。脚本生成 `auto-evaluation.json`，任何自动检查失败都会停止准备。若下载文件的哈希与固定版本不符，脚本也会停止。运行不需要外部模型服务，也不需要 Neo4j；正式路线仍采用另一证据级别。

## 已验证的结果

- 本地固定版本 PDF：3 篇；自动核查候选关系：5 条；正式路线记录：0 条。
- A 已掌握模仿学习：扩散模型 → Diffusion Policy。
- B 已掌握扩散模型：模仿学习 → Diffusion Policy。
- 两种预览均由路线生成器产生，API 返回 200；原文段落 API 返回 200。
- 同一资料集调用正式路线接口返回 422，因为自动核查与正式人工核验是不同的证据级别；自动核查预览不冒充正式路线。
- 后端路线与 API 相关测试通过；前端生产构建及路线页面测试通过。

这些结果证明流程可运行和分支确实随画像变化。它们尚不能证明路线对真实学习者更有效，也不能证明 Diffusion Policy 性能被复现。每周可用时间当前只记录在画像中，不参与阶段时长计算。

当前执行环境的浏览器自动化因 Windows 沙箱辅助进程启动失败，尚未完成截图级视觉核查；页面代码已通过生产构建。正式录屏前需按上面的步骤打开页面，检查双栏在投影分辨率下的排版和按钮交互。
