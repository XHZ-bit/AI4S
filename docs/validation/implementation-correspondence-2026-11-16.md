# 论文、源码与教学实践对应验收

日期为 2026 年 11 月 16 日。功能入口在节点详情的“来源”页和深入学习页，展开“论文与代码对应”后操作。

## 实现范围

- 同一研究空间内选择代码资料，优先使用已有实现关联，再按函数、符号及上下文检索。主动生成时，可用模型最多请求一次，输入仅包含有界的候选片段。离线时使用明确标记的规则候选。
- 每个候选保存双方逐字片段、来源、论文位置、代码行、版本和说明。允许手工建立、改选、修订、确认和否定。确认使用当前账号身份，本机未登录时记录“本机用户”。
- 同一函数可有多个不同符号的对应。重新生成保留人工决定，并抑制已确认或已否定片段的重复推荐。并发生成的最终写入使用事务，再次读取最新决定后去重。
- 来源代码的已确认对应投影为图谱中的 `IMPLEMENTED_BY`，供现有讲解检索复用。教学实现保留教学性质。两侧依据缺失或无法定位时，允许保存待核对内容，确认需要有效的双方证据。
- 对应保存证据快照与双方版本。来源、知识节点或依据改变后提示复核，旧对应及旧运行结果继续保留。即使其他分析重写同一个证据 ID，旧快照也不会重新显示为当前有效。
- 桌面并排核对双方摘录，窄屏或节点窄栏可切换。双方出处可进入现有阅读器并返回原位置。默认显示三条未核对候选，其余按需展开。
- 已确认的有效对应可以进入节点现有 Python 练习。运行记录保存对应版本快照、预测、输出和个人解释。成果导出支持选择对应及练习，保留完整代码提交号、固定链接、行号、历史核对状态和运行时快照。

新增接口位于 `/api/projects/{project_id}/knowledge/nodes/{node_id}/implementations`。GET 读取已有内容，POST 建立手工对应，POST `/generate` 主动生成，PATCH `/{mapping_id}` 按 `expected_revision` 修订。新表 `kw_implementations` 按空间和节点保存对应，历史修订复用 `kw_history`。既有节点和旧笔记继续沿用已有入口与存储。
