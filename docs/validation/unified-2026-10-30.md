独立发行包 HTTP 验收发现：前置关系中同时有直接路径和较长路径时，共用最短深度剪枝会漏掉较长路径上的中间知识。已仅对前置遍历取消这项剪枝，保留单路径循环检查、深度、结果数与总访问上限；普通两节点路径查询不变。新增收敛路径与循环回归，并加强原创演示的链式法则前置断言。修复前断言实际失败，修复后相关两文件 27 项通过，随后重新完成上表 753 项全套回归；原始日志为 `unified-2026-10-30/backend-final-prerequisite-tests.log`。

首次独立安装发现 Vite 8.3.0 的安全公告以及 Vitest 的关联问题。本机演示实际运行 Vite，因此已将 Vite 固定到 8.3.3、Vitest 固定到 5.0.3（关联 mocker 同步更新），重新执行完整前端回归和构建。补丁后的全量与生产依赖 `npm audit` 均为 0 项；结果仅代表本次公告库检查。[Vite 公告](https://github.com/vitejs/launch-editor/security/advisories/GHSA-587h-7wmj-h5pm)、[Vitest 公告](https://github.com/vitest-dev/vitest/security/advisories/GHSA-qxg6-89mg-rqv8)。原始审计 JSON 及安全补丁后的日志保存在本页证据目录。

同次安装还发现当前机器的全局 npm 缓存不可写；安装脚本已改为临时使用项目内 `.tmp/npm-cache`，结束时恢复调用者环境，不更改全局 npm 设置。最终源码包复现将再次验证这个修复。

## 统一与迁移

在已停止服务的真实资料备份副本上执行导入版本 2，再重复执行一次。检查本地根资料库及七个已注册账号资料库，共八个数据库：

- SQLite 完整性均为 `ok`；原节点、关系 ID 和 `user_fields` 人工修订保留。
- 406 条旧知识的原审核等级保留；资料库覆盖全部 14 篇已有论文，包括未归属研究空间的论文。
- `kw_nodes`、`kw_edges`、`kw_evidence`、`kw_sources`、`kw_legacy_map`、`kw_history`、`kw_model_calls` 的第二次迁移前后内容完全一致。
- 历史研究事实、冻结快照及旧审核表保持；模型调用数没有增加。
- 资产经过哈希验证并重定位到各自恢复后的账号目录，避免误读原资料目录。
- 三个研究空间的新 `/api/knowledge/graph` 与兼容 `/api/graph/overview` 在同一筛选及 500 节点上限下返回相同节点 ID。

空类型等异常旧字段保留原始载荷与缺失标记；没有用模型补造字段或证据。人工图谱修订和审核对迁入的旧研究事实生成兼容新版本，使旧正式规划读取更新并提示成果过期；冻结快照内容保持原义。

真实库随后完成停服备份和原位切换：8 个业务库及身份库完整，2,593 个既有节点/关系、593 项历史表检查和 406 条原审核等级通过保留校验，14 篇原论文进入资料库。21 项可用原件通过哈希与作用域路径检查，9 项历史缺原件记录继续明确标记。第二次迁移的七张统一表内容摘要完全相同，未跳过账号作用域，模型调用增量为 0。脱敏结果为 `unified-2026-10-30/live-cutover-summary.json`；本机备份与最终运行身份见发行包旁验收报告。

真实资料验收还发现总览排序把旧 `type=paper` 的同名实体误当作来源优先，占据首屏。已增加显式只读 `overview=true` 投影：验证真实来源根身份，跨作用域轮流展示并限制上限；默认全量查询和分页保留原语义。来源显示空间及可见知识数量，展开时优先呈现知识节点；同名历史记录保留原 ID 并显示记录号，仍可搜索。真实页面首屏现为 22 个来源入口，覆盖资料库和两个非空空间。库关系证据按实际来源定位；无论文 UID 的报告/代码沿空间来源读取，不构造空论文链接。

来源详情深链接还补充了同一只读根标记和精确知识数量，保证从原文返回后仍能展开来源。此小型响应补充位于 757 项全套之后，由包含两项新增详情回归的 26 项图谱专项再次通过（5.29 秒），完整 Ruff 同时通过；没有把该专项冒称又运行一次完整后端。日志为 `unified-2026-10-30/overview-final-detail-tests.log` 和 `overview-final-ruff.log`。
