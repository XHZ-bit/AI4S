## 实现内容

### 1. 课题列表与设置

- 空项目状态、项目状态/领域/版本展示、创建课题表单。
- 编辑课题名称、研究问题、首轮验证目标、数据集、指标、数据访问与其他约束。
- 写操作使用同步锁避免 React StrictMode 或重复点击造成重复创建/保存。
- 409 时保留当前表单并明确提示人工重新加载和合并，不静默覆盖。

### 2. 资料与证据

- 从既有论文库选择并关联论文；复用既有 PDF 上传能力，上传结果不冒充已关联或已抽取。
- 启动抽取任务、轮询字符串任务 ID、停止于成功/失败/中断，失败重试会显示为新任务。
- 展示方法、实验设置、测量、来源类型、查找状态、审核状态与逐字段证据抽屉。
- 支持候选 → 用户确认/争议/撤回和撤回 → 候选的人工状态操作，要求审核人和理由。
- 方法/实验设置内容修订在公共写接口缺失时只保存为浏览器本地草稿，并明确标为“未保存到服务端”；没有伪造成功响应。
- 部分抽取、未知值、缺失测量、上传失败和模型/任务失败都有明确状态；未知不显示为 0。

### 3. 候选比较与路线选择

- 多选方法+实验设置候选，逐项展示数据集、划分、协议、字段来源和缺失说明。
- 单独展示“课题约束匹配”和后端返回的“文献实验条件检查”，不将二者混写。
- 后端不可比组只并排显示，不生成跨组排名。
- 用户选定路线时必须填写理由；保存内容保持 `user_input` 语义，409 时保留选择与理由。

### 4. 方案、历史、导出与打印

- 从已保存决策启动方案生成任务；生成失败时历史方案仍然可读。
- 方案草稿支持目标、假设、假设条件、未知项、步骤、验收标准、测量和风险编辑。
- 本地草稿持续保存到 `localStorage`，刷新后恢复；确认后才调用版本化保存 API。
- 展示方案版本历史、`needs_review` 原因并创建不可变快照。
- 快照提供 JSON/Markdown 导出链接，专用打印页可用浏览器“保存为 PDF”。
- 打印页不会隐藏未保存、草稿、待复核、未知、风险、缺少依据或冻结引用状态。
- 未保存草稿也可打印，但页首明确标为“未保存的本地草稿”，不会冒充快照。

### 5. 完整课题图谱页面

- 独立 `ProjectGraph` 页面只按 URL 中的 `project_id + snapshot_id` 调用冻结图查询接口；响应身份不一致时拒绝显示。
- 方法、实验设置、测量、证据、决策和方案使用不同类型标签与颜色；同名不同 ID 的实验设置不会合并。
- ForceGraph 支持缩放、拖拽、画布适配、节点选择；“局部展开”只增加一跳邻域。
- 默认只显示当前计划/决策/方法的一跳任务子图，不一次堆满完整投影；支持按节点类型筛选。
- `mode=evidence` 展示方案→决策→实验设置/事实→证据的可阅读路径；证据节点显示原文片段、来源、核对状态及论文/章节跳转。
- `mode=method` 从方法卡深链接进入并展示多个独立实验设置、测量和证据。
- `mode=impact` 高亮证据到决策/方案的直接或间接路径，并明确“需要复核不等于方案已经错误”。
- 展示图 revision（快照版本+ID）、同步检查、待同步、失败、空图和版本不一致状态；历史 revision 明确标为历史。
- 请求带 AbortController 和递增 request ID；切换课题/快照后，旧响应不能覆盖新图。
- 失败状态保留返回方案与已保存资料入口；不生成演示节点或复用旧全局图谱冒充结果。
- 方案快照、方法卡和证据抽屉分别提供“查看依据”“查看实验设置”“查看影响范围”深链接。

## 接口或公共文件变更申请

### A. 事实内容人工修订接口缺失

当前冻结 API 只有状态流转，无法把用户对 `MethodCard` / `ExperimentSetting` 的字段修正保存为新事实版本。
建议 T0 增加公共请求模型和写入口，例如：

```text
PUT /api/projects/{project_id}/facts/{fact_id}
request: expected_version + actor + reason + replacement fact payload
response: MethodCard | ExperimentSetting | Measurement（新版本）
```

要求：服务端强制 `source_kind=user_input` 或逐字段保存用户来源，保留旧事实版本与审计，标记相关快照
`needs_review`；不得把人工修正改写成 `literature_report`。T4 当前的本地草稿可在接口冻结后接入。

### B. 首次方案保存的 ID 语义不明确

公共模型允许未保存方案 `id=null`，但 API 是 `PUT .../plans/{plan_id}`。T4 当前首次保存生成稳定客户端草稿 ID，
并将其同时放入路径和方案正文。请 T0/T1 明确以下二选一并同步契约：

1. 明确允许客户端生成首次 `plan_id`；或
2. 增加 `POST /api/projects/{project_id}/plans`，由服务端分配 ID。

### C. 方案生成任务结果形状

`AsyncTask.result` 当前是开放字典。T4 同时兼容 `result` 直接为 `ValidationPlan` 和 `result.plan`；建议 T0/T1
冻结为一种形式并增加契约测试。

### D. 图投影同步元数据

当前 `GraphQueryResult` 只有 `project_id/snapshot_id/nodes/edges`，没有服务端投影 revision、排队状态或失败原因。
T4 当前用不可变快照的 `snapshot_version + snapshot_id` 作为页面 revision，并把 404 解释为“待同步”、503 解释为失败。
建议 T0/T5 在不改变节点/边结构的前提下增加只读投影状态响应或独立状态端点，至少提供
`snapshot_id/snapshot_version/status/updated_at/error`，避免前端只能从 HTTP 状态推断同步阶段。
