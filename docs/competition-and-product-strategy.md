# Research Atlas 比赛产品与实施总纲

## 核心定义

Research Atlas 不是普通论文问答工具，而是“以知识图谱为底层，以科研学习路径为核心，以用户成长结果为评价标准的科研入门智能体平台”。

## 用户闭环

```text
上传论文/资料 → 抽取知识和证据 → 构建关系图谱 → 识别知识缺口
→ 生成个性化学习路径 → 阅读/练习/复现 → 测验反馈
→ 更新掌握度 → 动态调整路线
```

## 比赛差异化

普通系统回答“这篇论文讲了什么”；Research Atlas 进一步回答“你现在缺什么、应该先学什么、如何学会、证据在哪里”。

## 首期技术取舍

- GLiNER/领域 NER + LLM：降低实体抽取成本；
- BM25 + 向量 + 图一跳扩展：兼顾精确检索和关系检索；
- LightRAG/KG²RAG 思路：适合中小规模低成本部署；
- 图算法生成路线骨架，LLM 负责语言包装；
- claim 拆解、证据绑定和拒答：提升可信性；
- Graphiti 作为后续动态学习记忆方案。

## MVP 必须完成

1. 上传 3—10 篇具身智能/RL 论文；
2. 提取实体、方法、数据集、概念和前置关系；
3. 审核关键关系并写入 Neo4j；
4. 展示目标论文的前置知识图谱；
5. 根据目标、基础和时间生成 2—4 周路线；
6. 每周包含阅读、练习和一个实践任务；
7. 通过自测更新掌握度；
8. 对无证据问题拒答并展示原文证据。

## 比赛演示

用户会 Python 和基础深度学习，但不懂强化学习和扩散模型，目标是三个月入门具身智能并复现 Diffusion Policy。系统应识别缺口，生成四周路线，展示推荐依据；用户答错后增加补充任务；对资料不存在的数字明确拒答。

## 北极星指标

用户在目标周期内完成并验证的科研能力任务数，而不是图谱节点数量。

## 当前最关键的下一步

把“论文证据 → 知识关系 → 用户缺口 → 可执行任务 → 掌握度变化 → 路线调整”做成真实闭环。新功能优先级低于可信证据、任务完成标准和用户成长验证。
