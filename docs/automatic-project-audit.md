# 课题自动核查（project-audit-v1）

课题页的“自动核查”标签和 `GET /api/projects/{project_id}/audit` 从现有 SQLite 事实、证据、论文关联、方案及不可变快照实时计算结果，不写入或升级这些记录。接口返回规则版本、输入指纹、按严重度计数、稳定问题 ID、相关事实与证据、受影响的方案和快照。输入变化后刷新会得到新的指纹；旧方案和快照仍可查看。

当前检查范围：冻结文档是否存在且版本匹配、仅摘要资料、更新的文档版本、事实来源是否仍有效、字段证据是否存在且属于当前冻结文档、原文片段和引文是否可定位、记录中的冲突状态、数据集/划分/协议缺口，以及同名指标跨设置时范围、量纲、划分和协议的差异。对同条件同方法但报告值不同的记录只提示“报告值不同”，不判定哪篇论文正确。成对测量检查最多读取按 ID 排序的前 100 条有数值记录；超出时明确提示未检查部分。

`blocking` 表示机器可复现的来源链断裂，`warning` 表示比较条件或已知状态需要核查，`notice` 表示版本或报告值变化。所有级别都只代表自动核查，不改变 `research-v1.1` 的事实状态，不生成正式路线，也不证明主张、科研结论或学习效果。无模型、无 Neo4j 时仍可使用。

知识质量页另有“自动诊断”标签，调用 `GET /api/learning/relations/audit`，对候选、自动核查预览、演示预览和已核验关系进行结构、精确引文、来源归属、同名歧义与先修环路检查。它只返回问题、受影响关系 ID 和输入指纹，不会改变状态或把机器通过的关系加入正式路线。旧版 `legacy_unverified` 不会因新诊断而自动升级。

路线页另有“机器核查候选路线”，从 `GET /api/roadmap/auto-targets` 选择 `auto_checked` 目标后调用 `POST /api/roadmap/auto-preview`。服务端重新检查该级别的所有关系类型、引文偏移、来源归属与先修环路，再生成不持久化的路线并标注估算排期。缺少论文关联、关系检查失败或目标歧义时返回明确错误。正式 `/generate` 和 `/replan` 的人工核验要求不变。

论文库使用 `GET /api/search/v2`：本地标题、摘要与已保存原文片段检索始终可用；有可用 embedding 与模型时再融合语义排名。返回匹配原因和片段；排序分数仅表示相关性。旧 `/api/search` 语义保持不变，便于已有调用方迁移。当前词项匹配会扫描本地记录，适合单机试用，不宣称大规模索引性能。

课题“本地资料雷达”通过 `GET /api/projects/{project_id}/radar` 发现尚未关联课题、但标题或摘要包含已知方法名或数据集名的本地论文；列出命中原因与可能受影响的已存方案。它在论文进入本机库后自动可见，不单独联网抓取，不推断新论文对旧结论的科学影响。结果最多显示 50 条，`total` 保留全部匹配数。

后端验收：`cd backend; python scripts/test.py -q tests/test_assistant.py`。测试使用隔离合成资料，注入引文改写、文档版本变化和条件不兼容，验证报告变化及影响范围。前端构建：`cd frontend; npm run build`。
