# Research Atlas 下一阶段平台建设计划

日期：2026-10-04。负责人：T0。基础版本：`research-v1.1`。

## 目标

先消除“不授权外部模型就无法完成核心流程”的产品阻断，再补齐失败恢复、浏览器验收和真实服务验证。保持 SQLite 为事实真源，不改写旧论文、学习记录、路线或固定案例。

## 当前并行任务（已完成）

### T4：人工方案 fallback

范围：`frontend/src/pages/research/`、`frontend/src/components/research/`、`frontend/src/api/projects.ts`、`frontend/src/__tests__/research/`。

交付要求：

- 生成 provider 不可用时，保留明确失败信息和已保存历史；
- 用户可创建 `source_kind=user_input` 的本地结构化草稿，填写目标、未知、步骤、验收条件与风险；
- 通过现有 `PUT /plans/{plan_id}` 保存，不新增或放宽公共契约；
- 草稿、已保存方案和不可变快照视觉上明确区分；
- 不预填实验成绩、显存、耗时或资源结论。

### T1：后端失败与恢复加固

范围：T1 存储、服务、项目 API 与 T1 测试。

交付要求：

- 无方案 provider 时异步任务最终为 `failed`，错误不是空对象或假成功；
- 进程重启将未完成 research 任务标为 `interrupted`，运行中投影标为失败且可重试；
- 约束版本更新遵守乐观锁并精确标记受影响快照；
- JSON/Markdown 导出始终来自不可变快照，包含冻结文档与事实引用；
- 所有测试只使用临时 SQLite 和 mock。

### T6：验收扩展

范围：T6 acceptance 测试、评估脚本和内部验收文档。

交付要求：

- 将人工方案 fallback 加入核心流程验收；
- 覆盖无 provider、模型超时、图失败/重试、409、约束变化、JSON 内容和打印边界；
- 明确区分 mounted HTTP + mock、静态门禁、真实浏览器和真实服务；
- 旧论文、学习记录、路线与固定案例继续回归。

## T0 集成顺序

1. 检查 T1/T4/T6 handoff 和文件稳定性，拒绝越权修改或契约漂移。
2. 先合并 T1 的失败语义测试，再审 T4 是否完全复用现有类型/API。
3. 接入 T6 新验收并运行后端全量、Ruff、前端全量、生产构建和统一 runner。
4. 只有人工方案 fallback 能在无模型时完成“编辑 → 保存 → 快照 → 导出”，且生成任务仍明确失败，才重新评估 10 月 9 日核心冻结。

## 后续授权任务

以下工作不在当前并行实现中，需用户或项目负责人确认后启动：

- 外部方案模型允许发送的字段、服务地址、日志脱敏和数据保留策略；
- 隔离环境真实模型、Neo4j、GROBID 和断网测试；
- 浏览器人工全流程、窄屏/刷新和打印为 PDF 的视觉验收；
- 真实论文 gold、A/B/C 内部任务对照、外部用户试用；
- 报告、PPT、视频脚本、录制和第三方许可清单。

## 冻结门槛

核心开发可冻结必须同时满足：

1. 无模型环境能查看历史并通过人工输入完成首轮方案保存/快照/导出；模型生成请求明确失败。
2. 陌生资料不需要修改业务代码；方法、设置与测量不混合；未知值不被补全。
3. 图服务失败不丢 SQLite 数据；可重试且查询限定项目与快照。
4. 409 不覆盖新版本；事实、证据、论文关联和项目约束变化可发现受影响快照。
5. 后端全量、前端全量、生产构建、统一 acceptance runner 全部通过。
6. 未验证的真实服务、浏览器和人工评测继续单列，不得用 mock 替代。

## 完成结果

- T4：人工方案 fallback 已交付；模型失败仍可见，人工草稿固定 `user_input`，支持首次保存、本地恢复和防覆盖。前端 Research 定向 22 项通过。
- T1：新增无 provider 任务失败、重启恢复/投影重试、约束冲突与影响、冻结导出回归；未发现新的生产缺陷。
- T6：统一 runner 扩展为 Research 108 项、全部旧后端 116 项、打印页 2 项和静态门禁 11/11。
- T0：前端全量 33 项、生产构建和完整 Ruff 均通过。

结论：六项核心开发冻结门槛均有自动化证据，2026-10-09 核心代码可冻结。真实服务、人工浏览器/PDF 和人类评测仍属于 10—14 日发布验证，不得标记为已完成。
