# 方案模型 provider 接入前审批清单

状态：待审批，不代表已授权。当前生产行为仍是 provider 不可用并明确失败。

## 必须确认

1. 服务与地域：模型供应商、API 基础地址、处理地域、是否经过代理。
2. 允许发送的数据：课题标题/问题、用户约束、方法与实验设置字段、测量、证据原文、文档标识分别选择允许或禁止。
3. 明确禁止：API 密钥、文件系统路径、数据库路径、用户身份信息、未授权原始 PDF、环境变量和内部日志。
4. 数据保留：供应商是否保存请求/响应、保留期限、是否用于训练、删除途径。
5. 日志：服务端只记录任务 ID、模型名、耗时、状态和脱敏错误；不得记录 prompt、原文片段或凭据。
6. 用户提示：发送前显示来源范围与用途；模型建议始终标为 `model_suggestion`，不能转写为文献事实。
7. 失败语义：无密钥、超时、429、5xx、无效 JSON、越权证据 ID、命令和无依据成绩均使生成任务失败或拒绝相应建议，不能返回假成功。
8. 测试：自动测试只使用 fake provider；真实调用需要单独授权、隔离数据与费用上限。

## 推荐的最小载荷

优先发送结构化、最小化的数据：项目领域与目标、用户确认的方法/设置字段、已选择的测量名称及查找状态、允许引用的证据 ID。除非单独批准，不发送证据全文、论文全文、用户备注或文件路径。

模型输出只允许附加方案步骤：标题、目的、输入、过程描述、预期观察、验收条件和现有证据 ID。输出不得包含可执行命令、声称已实测的成绩、推测的资源/耗时或新的论文事实。

## 审批后实施顺序

1. T0 冻结 provider 输入/输出类型和错误码。
2. 在独立适配器中实现最小载荷、脱敏日志和超时；不把外部 SDK 扩散到业务模块。
3. 用 fake 覆盖所有错误分支；真实调用只用授权的合成/公开材料做一次隔离验证。
4. 通过后再开放 UI 生成按钮；人工方案 fallback 永久保留。
