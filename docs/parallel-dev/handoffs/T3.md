## 实现内容

### 两种比较严格分离

- `compare_candidates_to_constraints(project, facts)`：候选方法/实验设置与用户课题约束比较，逐维度给出“已知冲突 / 尚未发现冲突 / 信息不足”。
- `compare_conditions(request, facts)`：文献实验条件比较，逐维度给出“已核对维度一致 / 存在差异 / 信息不足 / 存在差异+信息不足”。
- 每个 `ComparisonDimension.reason` 使用稳定格式同时保留判断、差异、缺失、证据、冲突证据和限定说明；差异不会掩盖缺失。
- 不生成综合分数、排行榜、默认赢家或自动决策。不同关键条件签名进入不同 `ComparisonGroup`，并明确禁止跨组按测量值排序。
- 字符串只做大小写/空白规范化，不因名称相似推断同一数据、设置或方法。
- 时间与内存只在固定单位因子可证明时换算，并保留原始值和换算依据；货币或未知单位不换算，保留为信息不足。

### 两个领域配置

- 图像异常检测：数据集/版本、缺陷范围、监督信息、异常样本使用、预训练来源、划分、输入设置、预处理、协议、图像/像素指标范围、指标、数值尺度/单位和聚合方式。
- 时间序列预测：数据集/版本、数据子集、单/多变量、目标变量、输入长度、预测长度、频率、标准化、时间划分、协议、指标、数值尺度/单位和聚合方式。
- 配置只描述比较维度和字段别名，不含具体论文答案、目标分数、偏好方法或预设赢家。
- fraction/percent 只在数学上可证明时使用同一规范尺度；原始 scale/unit 始终保留在输出值中。

### 决策校验

- `validate_decision` 校验项目版本、事实项目归属、所选方法、设置—方法关系、撤回状态、考虑过的候选和证据绑定。
- candidate、disputed、unknown/not_found/not_parsed/conflicting、缺少指标和缺少资源都保留为明确警告；不会替用户更换选择。
- 决策证据必须能通过 `FieldEvidence` 绑定到所选或被考虑事实；用户理由始终作为用户选择，不改写成论文结论。

### 方案草稿与快照内容

- `build_plan_draft` 生成可人工编辑的结构化草稿，覆盖目标、路线、来源、数据与划分、基线、指标、控制条件、步骤、产物、判断标准、风险和未决事项。
- 默认不调用模型，标题和 unknowns 明确标记“结构化待填模板”；模型回调异常时保留模板并明确说明不可用，不伪装生成成功。
- 可选模型建议只允许追加带当前证据 ID 的步骤；未经确认的 shell/训练命令、无证据步骤和疑似未核验实测成绩会被拒绝写入步骤并转成未决项。
- `build_snapshot_content` 只接受用户确认且已保存的方案，冻结项目、约束、领域配置、决策、文档、事实和方案版本；校验文献证据属于冻结文档。
- 所有函数无数据库/图服务写入，不修改传入对象；快照输入不变性有测试覆盖。

## 对其他任务的依赖

- T1 调用：

- T1 应为正式快照分配持久化 ID、项目内 snapshot_version 和真实创建时间；当前 `build_snapshot_content` 生成确定性内容 ID、`snapshot_version=1`，并用冻结项目 `updated_at` 作为无副作用的占位时间。
- T2 需保证候选 `FieldEvidence.field_path` 与字段/NamedValue 名称可对应；T3 对未知别名保持信息不足，不猜测。
- T4 需要展示 `ComparisonDimension.reason`、`groups.reasons` 和 warnings，不能只展示 `comparable` 布尔值或自行生成排名。
- T5 可从 T1 保存后的 `ProjectSnapshot.frozen_facts`、step evidence IDs 与 frozen documents 建立投影。

## 接口或公共文件变更申请

以下仅为申请，T3 未修改公共文件：

1. **`ComparisonRequest` 缺少显式领域。** `CandidateBundle` 也没有 domain。当前 T3 只能在指标/字段提示唯一时推断；提示为空或同时命中两个领域会明确 `ValueError`，不会猜测。建议 T0 给 `ComparisonRequest` 增加 `domain: DomainId`，或把冻结签名改为接收 `ResearchProject`。
2. **`ComparisonDimension` 无法结构化承载本任务要求的判断。** 建议增加 `mode`、`judgement`、`difference_reasons[]`、`missing_items[]`、`evidence_ids[]`、`conflicting_evidence_ids[]`。当前兼容实现把这些内容编码在稳定格式的 `reason` 中，`comparable=false` 无法单独区分差异和缺失。
3. **`DecisionValidationRequest` 不含 `EvidenceRef[]`。** 当前只能确认 evidence ID 绑定到当前事实，不能直接校验 EvidenceRef 的文档/冲突组。建议增加 `evidence: list[EvidenceRef]`。
4. **`ValidationPlan` 缺少 project_version、依赖事实版本、计划级 evidence IDs、生成状态，以及结构化 baseline/data/control/artifact 字段。** 当前内容放在 ProtocolStep/unknowns，正式版本依赖由 `ProjectSnapshot` 冻结。建议增加 `frozen_project_version` 或单独的 `PlanDraftEnvelope`，并增加 `generation_status=template|generated|failed`，避免仅靠标题表达模型不可用模板。
5. **`SnapshotBuildInput` 没有 snapshot ID、序号和创建时间，但返回类型要求完整 `ProjectSnapshot`。** 建议拆分 `SnapshotContent`（T3）与 `ProjectSnapshot`（T1 持久化），或给输入增加由 T1 分配的 `snapshot_id/snapshot_version/created_at`。
